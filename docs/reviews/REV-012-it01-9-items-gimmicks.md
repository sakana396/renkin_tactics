- `go test ./...` は成功（`internal/core/tactics` の命令網羅率 99.2%）
- `go run ./tools/tccheck` は整合 OK（警告 4 件は手動のテスト）。CI（`gh pr checks 22`）も成功
- main とブランチのテスト仕様書の ID を比べ、取り除いた ID がないことを確かめた（追加 20 件、TC-NFR-07-04 は書き換え）
- `UseItem` の検証 6 の順、回復の上限、数を 1 減らして 0 で消すこと、砦の回復（切り捨て、0 なら `Heal` を出さない、倒れたユニットは除く）、増援（そのターンだけ、ふさがれたら後のターンにも現れない、その番は動かない）、敵軍の番の始めの出来事の順（`PhaseStart` → `Reinforce` → `Heal`）、勝ち負け（攻撃のたびに確かめる、決まったら止める、以後は `ErrBattleOver`）を、設計書 3.2・3.4・3.8〜3.10・3.13・3.14 節と照らした
- テストの期待値（砦の 4・4（24 の 4.8 を切り捨て）・5・0、回復薬の 10・10・5・1、増援の添字、勝ち負けの出来事の列と動いた敵）を、設計書の式とテストの能力から計算し直し、一致することを確かめた
- 実装を一時的に書き換えて、テストが誤りを見つけられるかを確かめた（ミュータント検査）。倒れたユニットも増援のマスをふさぐ、砦の回復で陣営を見ない、敵のループの中の勝ち負けの確認を外す、手持ちを減らすのを `Heal` のあとにする、`Won` で結果を変えない、ではテストが失敗した。敵のループのあとの勝ち負けの確認を外したときは、テストが通ってしまった（F-01）
- #10（PR #23、9898a8f）と試しにマージした。文面の衝突はないが、TC-FR-MAP-03-01〜03・05〜07、TC-FR-BTL-03-07 の 12 のサブテストが失敗した（F-02）。対応のあと、実装担当が #10 と合わせてテストが通ることを確かめた
- `SetEnemyTarget`・`SetHP`・`KillUnit` は `export_test.go` にだけあり、公開の API に入っていないことを確かめた

## 指摘と対応

| # | 指摘 | 区分 | 対応 |
|---|---|---|---|
| F-01 | 敵軍の番で、添字が最後の敵の攻撃で勝ち負けが決まったとき、ターンを進めずに止まること（3.10 節）を確かめるテストがない。`runEnemyPhase` のループのあとの確認を外してもテストが通る | 設計どおりへの修正 | 最後の敵の攻撃で主人公が倒れるケースを足し、確認を外すと失敗することを確かめた |
| F-02 | 砦・増援と TC-FR-BTL-03-07 のテストの期待値が、#10 までの「敵が何もしない」仮の動きに頼っていて、DES-AI-01 から導いた値になっていない。#10 と合わせると 12 のサブテストが失敗する | 設計どおりへの修正 | 敵軍の番の中身を確かめないテストでは `SetEnemyTarget` で敵を止める形にし、テスト仕様書に前提を書き足した。#10 と合わせて通ることを確かめた。#10 は main を取り込み、CI を再実行してからマージする |
| F-03 | テスト用の差し替え口 `actEnemyOverride` が本番の `Battle` の非公開の欄にあり、`runEnemyPhase` に分岐がある。公開の API と本番の動きは変わらない | 情報 | 対応なし。#10 で分岐を残すよう申し送り済み |
| F-04 | TC-NFR-07-04 は ID を残し、中身を「`UseItem` の検証 6 で失敗したら状態を変えない」に書き換えた（REV-007 F-02 の予定どおり） | 情報 | 対応なし |
| F-05 | 敵軍の番の途中で勝ち負けが決まると、`Phase` は `Enemy` のまま残る。検証 1 が 2 より先なので `ErrBattleOver` を返す | 情報 | 対応なし。#12 に申し送り済み |
