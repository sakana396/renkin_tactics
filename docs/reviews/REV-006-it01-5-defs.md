## 検証

- `gofmt -l .` は出力なし。`go vet ./...`、`GOOS=windows go vet ./...` は成功
- `go test ./...` は `internal/defload` と `tools/tccheck` が成功。`gh pr checks 15` は成功
- `go run ./tools/tccheck` は整合 OK（警告 0 件）
- `go list` で import を調べ、`defs` は依存なし、`defload` は `defs` と `BurntSushi/toml` と標準ライブラリだけ、`data` は `embed` と `io/fs` だけであることを確かめた（DES-PKG-02・03・07）
- `data/base/*.toml` の値を、設計書 10.1〜10.4 節と 3.7 節に照らした。キャラとボスの能力（クラス ＋ ボーナス）を手で足し、10.3・10.4 節の「能力」の列と一致することを確かめた
- DES-DAT-03 の規則 1〜13 ごとに、実装とテストケースを照らした。テストにない場合（値の型の誤りの種類、範囲外の整数、キーの重複、書き間違えたキー、地形の定義が空）は、探りのテストで動きを確かめた（コミットはしていない）
- 規則 13 の道筋（配列の表、インラインの表、インラインの配列の表、入れ子の配列の表、いちばん上のキー、ドット付きのキー）を、一時的なテストで確かめた。本体のデータは規則 13 で誤りにならない
- 誤りの文面が、設計書と ADR-0003 の例（`characters.toml: characters[2].class: クラス "knight" がありません`）と同じ形であることを確かめた
- テストケース ID（TC-FR-SYS-03-01〜02、TC-FR-SYS-04-01〜20、TC-IF-03-01〜02）が、テスト仕様書・テストコード・トレーサビリティでそろっていること、トレーサビリティは担当の 3 行だけを変えていることを確かめた
- 管理役の Claude Code が、main（#16 のマージ後）と合わせても衝突せず、4 つの検査が通ることを確かめた
