## 検証

- `gofmt -l .` は出力なし。`go vet ./...`、`GOOS=windows go vet ./...` は成功
- `go test ./...` は成功（`internal/core/tactics` の命令網羅率 97.7%）
- `go run ./tools/tccheck` は整合 OK。CI（`gh pr checks 21`）も成功
- `go list -deps` で、`internal/core/tactics` が Ebitengine を import していないことを確かめた
- 設計書 3.5 節の計算例 1〜5（1' と 2 の反撃を含む）を 10 章の値から計算し直し、テストの期待値と一致することを確かめた。ほかのテスト（地形、相性、大盾、怒り、狙撃、予測の移動先）の期待値も手で計算し直した
- 乱数を引く順（1 撃ごとに 2 つ、当たって受ける側が大盾なら 1 つ）、1 撃の順（1 撃目 → 反撃 → 追撃）、倒れたら止めること、弓の反撃不可、怒りを 1 撃ごとに判定すること、鼓舞の距離（`To` で測る）を、設計書 1.2・3.5〜3.7 節と照らした
- `Forecast` が写した盤面の上で計算し、乱数を引かず、状態を変えないこと、実際の攻撃と同じ式（`strikeValues`）を使うことを確かめた
- 実装を一時的に書き換えて、テストが誤りを見つけられるかを確かめた（ミュータント検査）。守る側の追撃の条件「反撃できる」を外したとき、狙撃を反撃にも効かせたとき、移動しても狙撃が効くようにしたときに、テストが通ってしまった（F-01・F-02）。対応のあと、実装担当が同じ書き換えでテストが失敗することを確かめた
- `KillUnit`・`SetHP` は `export_test.go` にだけあり、公開の API に入っていないことを確かめた

## 指摘と対応

| # | 指摘 | 区分 | 対応 |
|---|---|---|---|
| F-01 | 守る側は「反撃できるときだけ」追撃する（3.6 節）ことを確かめるテストがない。TC-FR-BTL-06-02 は「反撃できない剣士は追撃もしない」とするが、ミラと剣士の速さの差は 2 で、追撃の条件を満たさない | 設計どおりへの修正 | 剣士の速さを上げた盤面で、予測の回数 0、`Strike` 1 つ、乱数 2 つを確かめるテストを足した |
| F-02 | 狙撃が反撃に効かないこと、移動すると効かないことを、`Forecast` だけで確かめていて、実際の `Act` では確かめていない | 設計どおりへの修正 | TC-FR-UNT-07-07 に、命中率の境目の乱数で `Act` するケースを 2 つ足した |
| F-03 | `Strike` の `Amount` の意味（必殺・大盾を入れた与えたダメージ。HP の残りで切らない）が、設計書 3.13 節にも `event.go` にも書かれていない | 情報 | `event.go` のコメントに書いた。設計書への追記は、次に設計書を直すときに開発者の承認を得る |
| F-04 | `ForecastSide.Crit` と怒りは回数 0 の側でも真になる。大盾は相手の回数が 1 以上のときだけ出すので、扱いがそろっていない | 情報 | 対応なし。#13 の表示で扱いを決める |
| F-05 | ダメージ 0 で当たったときに大盾の乱数を引くことを確かめるテストがない | 情報 | テストを足した |
| F-06 | `judge` は空で、#9 の勝ち負けを先取りしていない。`UseItem` は `errNotImplemented` のまま | 情報 | 対応なし。#9 に申し送り済み |
| F-07 | 大盾を効くスキルに出す条件（相手の回数が 1 以上）を確かめるテストがない | 情報 | テストを足した |
