## 検証

- `gofmt -l .` は出力なし。`GOOS=windows go vet ./...` は成功。Linux の `go vet`・`go test` は、X11 がないため ui・cmd を除いて成功。`GOOS=windows go test -c` で作った exe を `internal/ui` で実行して PASS（main の取り込みのあと）。`go run ./tools/tccheck` は整合 OK。CI は成功
- TC-FR-CMP-11-10・11 の ID は、仕様書・コード・traceability でそろっている。変えた行の列数・閉じの区切り・表の中の空行を確かめた（REV-031、REV-033、REV-042）
- 配置の表示は `Campaign.DeploymentView` の BoardView から作り、UI の中の地形の変換と HP だけの敵は消えた（REV-040 G-01）。範囲は BoardView の `Reachable`・`AttackRange` で求め、戦闘中の `ranges`・`Danger` と同じ定義（赤は青を除く。Hold の敵も含む）。未出現の増援は含めない（FR-CMP-11 v0.3）
- E-42 と 7.3 節と照合した。初期は OFF。ホバーで青と赤を出し、外すと消す。Q の押し始めで切り替え、個別の範囲と同時に出せる。選択中もホバーと Q が効き、選択と slots は変わらない。交換と空き枠への移動で計算し直し、選択の解除だけでは変わらない。敵のクリックは従来の理由を出す。準備に戻るときと戦闘を始めるときに設定を捨て、戦闘側の danger は false から始まる。描画の順番は 7.3 節どおり
- 5.1 節と照合した。取得に失敗したら理由を出し、盤面と範囲を空にし、配置を残す。表示と失敗では NextSeed を呼ばず、開始の前に検証し直して、成功したときだけ 1 回取る
- TC-FR-CMP-11-10 の期待値は、7×1 の一本道（味方の占有・弓の最小射程 2・Mov 0 のボス）から手で導ける。弓の青は {3,4,5}、赤は {1,2,6}、橙は {1,2,3,5,6}。空き枠に移すと、青は {2,3,4,5}、赤は {0,1,6}、橙は 0〜6
- TC-FR-CMP-11-05・06、TC-FR-UNT-09-12 の補強は、既存の確認を残したうえでの追加で、弱めていない。理由の文はいちばん長い core の誤りでも x=280〜796 で、Q の案内（x=16〜130）・2 行の案内・ボタンと重ならない
- 敵の騎兵は core の ClassName を持ち、unitTile は変わっていない。main の取り込みでの game.go の差分は、配置の入力と drawDeploy だけで、#77 の巻き戻し一覧の入力はそのまま残っている
- ミュータント 4 件を実装者とは別に行った。ホバーしていない敵を危険範囲に入れない変更、戦闘開始で設定を捨てない変更、SetDeployCursor の場面の判定を外す変更は、TC-FR-CMP-11-10 が落ちた。`enterDeploy` のリセットを外す変更は、観測できる違いがない等価なミュータントだった
