## 検証

- 差分は文書だけ
- `gofmt -l .` は出力なし。`GOOS=windows go vet ./...` は成功（Linux では `internal/ui`・`cmd/renkin` が X11 のヘッダがなくビルドできない。REV-014 I-01）
- `go test ./...` は core・tactics・defload・tccheck が成功
- `go run ./tools/tccheck` は整合 OK（警告は手動のケース）
- E-21 は開発者の発言の原文と一致した
- 予測の「後」の HP を、`tactics.Forecast` の値から 3.6 節の順で計算し直し、手計算と一致した。例 1: レオン 20→11、ソルジャー 18→8。例 1 でレオンの HP 9: 9→0「危険」、ソルジャー 18→13。例 2: ブラン 26→12、剣士 17→4。例 2 で剣士の HP 10: 10→0「撃破」、ブラン 26→26。例 4: ガルド 24→18、ファイター 24→15（設計書 5.6 節の計算例に載せた）
- `Reachable` は陣営を問わず同じ規則で動き、`AttackRange` は射程に入るマスをすべて返す。範囲と予測は `tactics` を変えずに作れる。相性の関数（`triangle`）は公開されていないので、画面の側で求める（DES-UI-07）
- bitmapfont に ▲ ▼ → ― × のグリフがあることを確かめた。武器の絵は、剣・槍・斧が Tiny Dungeon、弓が Tiny Town にある
- E-22 で選ばれなかった選択肢（役割の一言、武器の相性の行、移動と攻撃の色分け、動き方の表示）は設計に入っていない
