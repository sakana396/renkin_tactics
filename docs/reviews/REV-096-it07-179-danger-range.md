## 検証

- 全敵の塗り、固定の実線・破線とピン、カーソルの実線・破線と名前の印、描画順を DES-UI-29／DES-UI-08 と照合した。範囲の移動費は UI で独自に計算せず、戦闘は `Battle.Reachable`、配置は `DeploymentView` の盤面の `Reachable` を使う
- 配置の未出現の増援、戦死後の固定数、巻き戻し成功後の生存添字による再計算を確かめた。固定の一括解除は Q・選択・戦闘の状態を変えず、再生中と巻き戻しの一覧では受け付けない。失敗した操作が戦闘の状態を変える変更はない
- TC-FR-UNT-09-27・28、TC-FR-CMP-11-13 は TST-IT07・テストコード・traceability にそろっている。ZOC の部分は #173 と明記されている。既存ケースの変更は、F-04 を除き、敵の範囲を別の層に移した変更と対応する
- 期待値は配置の座標など固定値から導く検査と、core の `Reachable`・`AttackRange` と照合する検査がある。後者は UI 側の範囲計算の誤りを検出できる。描画そのものは形の関数と作成者の画像確認（`tools/shot`）に依存する
- レビュー時、`gofmt -l .` は出力なし、`git diff --check` は指摘なし。`GOOS=windows go vet ./...` と `go run ./tools/tccheck` は読み取り専用の環境で Go の作業ディレクトリを作れず実行できなかった。対応後の検査は実装者が行った（下の「対応後の検査」）
- #165・#166・#170 との統合では `internal/ui` の入力・描画、情報欄と配置の領域が衝突しやすい。特に `leftClick` の優先順、`drawInfo` の操作行、配置のボタンの領域を統合後に確かめる
