## 検証

- DES-IT07 5.1〜5.3 節（DES-AI-03・DES-DAT-05）、DES-IT06 10.2 節、E-118・E-120・E-121 と照合した。次の点は設計どおりである
  - 小隊長が倒れると、`groupKey`（到達領域）の単位で配下に崩れの印（`Unit.Collapsed`、`Battle.groupCollapsed`）が付く。元の `Approach` は書き換えない
  - 崩れた `hold` は初めて動くときに `charge` になる。崩れた配下は `groupPlan`・`groupDanger`・`groupGathering`・`groupEntered` を参照せず、番の始めの決定も書き換えない
  - 敵の番の途中で倒れたときは、まだ動いていない配下だけが寄る
  - 印は、撃破の出来事を出す前に更新する
  - 巻き戻しは写しで戻し、乱数は引かない
- 増援で小隊長が出られない（マスが埋まる、39 体）ときは、その一団の配下を初めから崩して出す。小隊長だけが出たら、現行の敵として動く。出られなかった個体は先送りしない
- 39 体の上限では、先頭の小隊長が出られなければ配下も出られない（Codex の気付き）。5.3 節の「配下だけが出るときは direct」と矛盾しないので、設計の変更は要らない
- defload は `commander = true` に、一意の `id`、`approach = "group"`、`ai = "hold"`、空でない `group`、`boss = false` を求め、それぞれ位置と理由付きで拒む。同じ一団名・同じ通れる地形の連結領域に小隊長を 2 体置くことも拒む（初めの敵と増援をまたぐ）。離れた同名の一団は受け付ける
- TC-FR-BTL-07-25 の前提を「小隊長の攻撃への反撃」に直した。反撃は攻撃した側にしか当たらない（DES-BTL-06）ので、元の文の盤面は作れなかった。設計 5.2 節と合う
- 担当の外の変更はない。本体データ（`data/base`）と画面は #172 が担当する
- ミュータント（レビュー時）: fall の崩れ・崩れた hold の charge・増援の崩れ・巻き戻し・領域の区別を外すと、該当のケースが落ちた。崩れた配下を一団の思考から外す 4 つの条件（ai.go:67、ai_group.go:23・56・406）は外しても落ちなかった（F-01）。対応後は 4 つとも落ちることを実装者が確かめた
- `gofmt -l .` は出力なし。`go vet`（ui・cmd を除く）と `GOOS=windows go vet ./...` は指摘なし。`go test`（core・tactics・defload・savefile・data・tools）は ok。`go run ./tools/tccheck` は OK（警告 84 件）
