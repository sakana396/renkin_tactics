## 検証

- DES-IT07 v0.5 の 4 章（DES-BTL-11・DES-DAT-05、4.2 節の式と 6 つの計算例、4.3 節の再移動）、3.2・3.8 節、DES-FML-01 2.2 節・5 章、E-118・E-120 と照合した。設計どおり: `zocCost` は相手軍で生きていて zoc を持つユニットが進入先の上下左右にいれば 1。何体いても最大 1、出発マスは数えない、自軍の重騎士は自軍に効かない、無視できる者はいない。`reachableWithin`（到達・攻撃位置・再移動・敵の騎兵の下がる先）、`dangerFor`（危険範囲）、`terrainDistances`（集合先は前向き、`groupMove` は逆向きで入る側のマスで数える）、`closeness`（近さ。入る側のマスの `Cost+Z`）が同じ規則を使う。再移動の残りは行動前の位置からの ZOC 込みの費用で求め、行動後はその時点の生存者で `CantoReachable` を求める
- 4.2 節の 6 例（TC-FR-MAP-01-06）と 4.3 節の行動前の費用 3・残り 4（TC-FR-BTL-03-21）は、期待値が設計の表と文から出ている
- 本体データは `skills.toml` の zoc と `classes.toml` の armor の `skills = ["zoc"]` だけ。`maps.toml` は変えていない。ガルドの大盾は変わらない（TC-FR-UNT-02-04）
- ミュータント（レビュー時）: 落ちた — ZOC を外す、重ねて +2、出発で数える、出るマスで数える、自軍の重騎士を自軍に効かせる、近さ・一団の経路から ZOC を外す、defload の数値・効果名の検査を外す。残った — 死んだ重騎士の ZOC を数える（F-04）、逆向きの経路で `next` を数える（F-05）、defload の同じ効果の重なり（F-06）、tactics の数値の検査（F-10）
- レビュー時に旧版の固定 seed を新版で流すと、04-25 は 14 本中 8 本が負け、04-26 は低め ch04 seed 2 が負け、04-24 は平均の名簿で ch03・ch04・ch05・ch09 が 20 seed 中 0 勝。テストは勝ちの確認を外して通していた（F-02）
- ui のテストを Windows 向けに作って WSL から実行すると、`TestZOCMarks` が `ReadPixels cannot be called before the game starts` で panic した（F-01）

- 対応後の検査: `gofmt -l .` は出力なし、`GOOS=windows go vet ./...` は指摘なし、Windows 向けの UI テスト実行ファイルのビルド成功、core・defload・savefile・data・tools の `go test` は成功、`go run ./tools/tccheck` は整合 OK（既存の未実装・手動ケースの警告 59 件）。UI の実行は WSL の `UtilBindVsockAnyPort: socket failed 1` で起動できなかったため、ビルドまで確認した
- #173 の測り直し: 今の打ち手は 23 組で計 34 勝（#172 後・#173 前は 43 勝）、賢い打ち手は計 101 勝（旧 129 勝）。ch04 平均と ch07 代役は両方の打ち手で 0 勝。具体的な seed・局面は TST-IT07 3 章と制作記録に残した

## F-01・F-03〜F-10 の対応（Claude のサブエージェント、e45a599 ほか）

- F-01: `internal/ui/zoc.go` に角印の線分を返す純粋な関数 `zocMarkLines(board, camera)` と、描く順の並び `battleLayers`・`deployLayers`・`rewindLayers` を作り、テストは座標と描く順で確かめる
- F-03: 思考が止まる不具合ではなく ZOC の正しい効果（ch09 で攻撃に使うガルドの ZOC でアーチャーが集合先に届かず、集合が遅れる）。除外をやめ、「章・一団・攻撃した相手・その一員」の組で、攻撃した自軍が ZOC を持つときだけ上限を 6 回の番に延ばす。TST-IT06 04-23・TST-IT07 3 章に書いた
- F-04: 撃破したときだけ届く再移動のケースと、戦死した重騎士の盤面（TC-FR-MAP-01-07）を足した
- F-05: 出発マスか集合先だけが ZOC の中にある非対称の盤面のテストを足した
- F-06: `zoc2` を足して `skills = ["zoc","zoc2"]` を拒むケースを足した
- F-07: 配置の画面で、カーソルの下が重騎士の隣なら案内欄 (240,552) に「相手の重騎士の隣: +1」を出す（開発者の答え E-127 で承認）。下見の生存者で角印を描くこと、描く順も確かめた
- F-08: 09-28 の ZOC の部分を #168 のサブテストの最後に入れ、traceability の種別を直した
- F-09: 説明を「隣のマスに入る相手の移動費 +1」にした
- F-10: `TestClassSkillsTactics` に、通せんぼに数値を付けると拒むケースを足した
- 角印の形と位置: 右下は装備の印、右上はピンとボスの印、下端は HP の棒が使うので、敵軍の角印をマスの左下（HP の棒の上）に、自軍は左上。角の長さは 5 px。描く順は「ユニット → 敵の範囲 → 角印 → 装備の印 → ピン」（3.8 節は「細い角印」としか書いていないので設計の範囲内）
