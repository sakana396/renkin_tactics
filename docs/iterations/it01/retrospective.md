## 1. 対象と根拠

反復 1 の計画書 H-01〜H-04 を振り返る。実装のレビューと、開発者が遊んだ評価を分ける。反復 1 の改善前の感想は E-21、改善後の感想は E-29〜E-32 にある。E-35 は反復 2 の版の感想で、反復 1 の成功の根拠にはしない。E-25 で予定した遊び比べのあとに、本書を下書きした。

判定は「成り立った」「一部」「成り立たない」「未検証」とする。テストが通っていても、遊んで確かめる仮説を検証済みにはしない。E-35・E-36 の要点は確認待ちである。

## 3. H-04: ふしぎ錬金に戻す形

管理役の `H04-summary.md`（調査対象: renkin `7ac067c`、fushigi `d295b01`）を入力とする。今回、ふしぎ錬金のコードを再調査していない。元の作業場所にある要点を、後で参照できるよう本書にも残す。行数の見積もりは実装の測定値ではない。

| 観点 | 調べの結果 | 判断 |
|---|---|---|
| 結ぶ口 | 新しく書く型・関数 11 個、約 260〜320 行の見積もり。比較対象の `core.NewBattle` は 301 行・11 関数 | この規模との比較では少ないとみなす。結ぶ口に寄せる狙いは一部成り立つ |
| 公開するもの | 型 23、定数 28、関数 1、メソッド 9、欄 3、誤り 11。core が必ず使うものは約 20 個と関数・メソッド 5 | 公開 API 全体と、接続に必須の部分を区別する |
| World の影響 | `Battle`・`LastBattle`・`InjuredUntil` の欄名を保てる。player・rank・quest・golem・craft・drawDrops・UseEffectOf は直さない見込み | 戦闘以外への変更は抑えられる |
| 消す・書き換える量 | core の戦闘 4 ファイル約 520 行、UI の戦闘約 400 行（14 関数）、テスト 1,259 行。renkin の UI 約 1,600 行を移して直す必要がある | 移植全体を「結ぶ口だけ」とは評価できない |
| tactics に足りないもの | 全滅による勝ち負け（R2）、回復以外のアイテムの効果・射程・範囲（R5）、自動戦闘（R11。ふしぎ錬金 FR-BTL-08） | tactics をそのまま写すだけでは足りない |
| ゲーム側の判断 | 規則の差 10 個（R1〜R10）: 行動順、勝ち負け、攻撃計算と能力の不足、前衛後衛とクラス、アイテムの効果、共有在庫と手持ち、負傷、地形、敵の動き、操作 | 元の遊びをどこまで置き換えるか、人の判断が要る |
| ID の衝突 | 調査時のテストケース ID 105 個のうち 39 個が衝突する。設計 ID も衝突する | 移植時に文書とコードを一緒に付け替える必要がある |

**ADR-0002 の見直しの提案**: 標準ライブラリだけに依存し、World と定義データを知らない境界を保つ。「結ぶ口の量」と「規則・画面の差し替え量」を分けて記す。勝ち負け・アイテム効果・自動戦闘の口、`UnitSetup.ID`・`Item.ID`、ID の付け替え（例: `TC-TAC-`）、UI を写す範囲、モジュール共有を再検討する条件を、移植の前に決める。これは提案で、ADR 本体は変更しない。反復 2 で加わった口は IT02-RETRO 3 章に記録する。
