# 反復 1 計画書: プロトタイプ

- 文書 ID: IT01-PLAN
- 版: 0.2（案。開発者の承認待ち）
- 作成日: 2026-10-20
- 入力: SRS-001 v0.1、CON-001 v0.3、E-02〜E-04、E-06、E-09、E-11、E-13、E-14、E-20〜E-23

## 1. 目的

戦闘の核が面白いかを、最小の実装で確かめる（PLAN-001 3 章）。キャラ 3〜4 人と中くらいのマップ 1 枚で、キャラの強みとマップの動かし方の両方を少しずつ確かめる（E-06）。

## 2. 確かめたい仮説

| ID | 仮説 | 確かめ方 | 関連 |
|---|---|---|---|
| H-01 | クラス・武器の相性・キャラごとのスキル 1 つで、「このキャラはここで強い」と見つけられる | マップを 2〜3 回遊び、キャラごとに「どこで役に立ったか」を振り返りに記録する | FR-UNT-02、FR-UNT-03、FR-UNT-07、FR-UNT-09、FR-BTL-05、E-03、E-13 |
| H-02 | 地形、ギミック 1〜2 個、2 種類の敵の動き方で、16 × 16 マスのマップでも、動かし方を考える楽しさがある | 同じマップを違う動かし方で攻略できたか、敵を「釣る」動きが生まれたかを記録する。32 × 32 マス（E-04）に大きくしたときの課題も記録する | FR-MAP-01、FR-MAP-03、FR-BTL-07、E-04、E-13 |
| H-03 | 自軍と敵軍が交互に動き、攻撃の前に予測が見えれば、命中が確率で決まっても、考えて動かせる | 運で負けたと感じた場面と、その理由を記録する | FR-BTL-02、FR-BTL-04、FR-BTL-08、FR-UNT-09、E-09 |
| H-04 | ふしぎ錬金の戦闘のコードを World から切り離した形に作り直すと、ふしぎ錬金に戻せる形になる | 切り出した戦闘を、ふしぎ錬金の World と結ぶのに要る型・関数の数と、ふしぎ錬金の側で直す箇所を数えて記録する。少なければ成り立つ（いくつなら少ないかは振り返りで判断する）。結果を ADR-0002（TBD-03）に反映する | CST-04、E-02、E-11、E-13、E-15 |

## 4. 作らないもの

- 成長（経験・レベル・成長率）、転職、支援（FR-UNT-04、05、06、08）
- 章立て、章の準備、章の結果、物語、仲間の加入、離脱・ロストの選択（FR-CMP-01〜08、10）。マップの中で倒れた自軍のユニットは、そのマップから外す（E-15）
- 32 × 32 マスのマップ、詰め将棋のマップ、スクロール（FR-MAP-02、04、06）（E-13）
- セーブとロード、タイトル画面（FR-SYS-01、02、IF-04、NFR-08）
- クラスのスキル（FR-UNT-07 のうち、キャラのスキルだけを作る）
- 錬金と品質（FR-ALC-01〜04。CST-05）
- 宝箱などマップで拾うアイテム（E-13）
- 性能の調整（NFR-01、02）

## 7. 進め方

1. 本計画書の承認
2. ユースケースと設計書（計算例つき）、ADR-0002 を書き、spec-reviewer のレビューと開発者の承認を経てマージする。設計では、とくに次を決める（上流の文書で設計に回したもの）
   - 出来事の記録を使うか（SRS 3 章、E-11）
   - ふしぎ錬金の前衛・後衛の役割を、クラスにどう置き換えるか（CON-001 7 章）
   - 品質つきのアイテムの使用を外す方法（PLAN-001 3 章、CON-001 7 章）
   - 番の進め方を、素早さ順から自軍と敵軍の交互に変える方法（PLAN-001 3 章、E-09）
3. 設計をもとに GitHub Issue（ラベル `it01`、マイルストーン `IT01`）を切る。Issue には依存と完了条件を書く
4. 実装は Codex が担当する（E-14）。Codex の利用枠が埋まっているときは、Claude Code のサブエージェントが実装する（E-20）。Claude Code は、Issue ごとのプルリクエストを spec-reviewer でレビューし、自動マージの条件を満たせばマージする
5. 遊んで評価し、振り返りを書く
