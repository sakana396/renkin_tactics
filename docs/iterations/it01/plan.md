# 反復 1 計画書: プロトタイプ

- 文書 ID: IT01-PLAN
- 版: 0.1（案。開発者の承認待ち）
- 作成日: 2026-10-20
- 入力: SRS-001 v0.1、CON-001 v0.3、E-06、E-11、E-13

## 1. 目的

戦闘の核が面白いかを、最小の実装で確かめる（PLAN-001 3 章）。キャラ 3〜4 人と中くらいのマップ 1 枚で、キャラの強みとマップの動かし方の両方を少しずつ確かめる（E-06）。

## 2. 確かめたい仮説

| ID | 仮説 | 確かめ方 | 関連 |
|---|---|---|---|
| H-01 | クラス・武器の相性・キャラごとのスキル 1 つで、「このキャラはここで強い」と見つけられる | マップを 2〜3 回遊び、キャラごとに「どこで役に立ったか」を振り返りに記録する | FR-UNT-03、E-03、E-13 |
| H-02 | 地形、ギミック 1〜2 個、2 種類の敵の動き方で、16 × 16 マスのマップでも、動かし方を考える楽しさがある | 同じマップを違う動かし方で攻略できたか、敵を「釣る」動きが生まれたかを記録する | FR-MAP-01、FR-MAP-03、FR-BTL-07、E-04、E-13 |
| H-03 | 自軍と敵軍が交互に動き、攻撃の前に予測が見えれば、命中が確率で決まっても、考えて動かせる | 運で負けたと感じた場面と、その理由を記録する | FR-BTL-02、FR-BTL-04、FR-BTL-08、E-09 |
| H-04 | ふしぎ錬金の戦闘のコードを World から切り離した形に作り直すと、ふしぎ錬金に戻す形（TBD-03）を決められる | 反復 1 の設計で ADR-0002 を書けたか、ふしぎ錬金の World と結ぶときに要るものを記録する | CST-04、E-02、E-11、E-13 |

## 4. 作らないもの

- 成長（経験・レベル・成長率）、転職、支援（FR-UNT-04、05、06、08）
- 章立て、章の準備、章の結果、物語、仲間の加入、離脱・ロストの選択（FR-CMP-01〜08、10）。マップの中で倒れた自軍のユニットは、そのマップから外す
- 32 × 32 マスのマップ、詰め将棋のマップ、スクロール（FR-MAP-02、04、06）（E-13）
- セーブとロード、タイトル画面（FR-SYS-01、02、IF-04）
- 錬金と品質（FR-ALC-01〜04。CST-05）
- 宝箱などマップで拾うアイテム（E-13）
- 性能の調整（NFR-01、02）

## 7. 進め方

1. 本計画書の承認
2. ユースケースと設計書（計算例つき）、ADR-0002 を書き、spec-reviewer のレビューと開発者の承認を経てマージする
3. 設計をもとに GitHub Issue（ラベル `it01`、マイルストーン `IT01`）を切る。Issue には依存と完了条件を書く
4. 実装は Codex が担当する。Claude Code は、Issue ごとのプルリクエストを spec-reviewer でレビューし、自動マージの条件を満たせばマージする
5. 遊んで評価し、振り返りを書く
