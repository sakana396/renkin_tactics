E-39 は、反復 3 を締め、4 点の要望を反復 4 の計画・設計にまとめてから承認を得る進め方の了承である。本書と [DES-IT04](../../03_design/design-it04.md) の具体案の承認とは分ける。IT03-RETRO v0.1 の残る評価も引き継ぎ、本書とあわせて判定・未確認の記録を確かめる。承認済みの SRS・ユースケース・既存設計・計画と発言記録は、本案では変更しない。

## 1. 目的

巻き戻す前に戻り先を盤面で理解できるようにし、H-11 の「どこに戻るか分からなかった」を解消する。騎兵をアーマーと見分け、配置時に敵の範囲を確かめ、増援の気配を読んで備えられるかを評価する（E-39）。敵の能力・数・出現時機・行動規則は変えず、難しいほうがよいという E-32 を守る。情報の追加による体感の難しさの変化は、遊んだ評価として記録する。

## 10. リスク

| リスク | 対策・判断 |
|---|---|
| 一覧が盤面を覆い、プレビューしても戻り先が分からない | 盤面全体を左に残す。行名と「行動前」を右に表示し、番開始前の実際のターン・陣営と行のラベルの違いも示す |
| 閲覧で乱数や回数を変える | Rewind・Resume・tactics.New を閲覧には使わない。深い写しと状態不変の自動確認を行う |
| 配置の範囲が開始後と違う | HP だけの敵表示を廃し、core の同じ変換と tactics の同じ範囲計算を使う。配置後・開始直後の一致を確認する |
| 予兆が正確すぎる／弱すぎる | 領域と曖昧な文だけにし、H-14 の結果で評価する。能力などを一緒に調整しない |
| 絵の代用で要望を満たしたことにしてしまう | 素材不足を明示する。代案は人の判断を待ち、未達と代案採用を区別する |
| プレビューの複製と全履歴で重くなる | 選択した 1 件だけを複製して再利用する。使用量・待ち時間を測り、履歴を黙って削らない |
| 未確認の合格扱い、レビュー・CI の抜け | 実装・自動・手動・遊んだ評価を分け、確認範囲と最新コミットの結果を記録する |
