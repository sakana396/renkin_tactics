## 1. 目的

巻き戻す前に戻り先を盤面で理解できるようにし、H-11 の「どこに戻るか分からなかった」を解消する。騎兵をアーマーと見分け、配置時に敵の範囲を確かめ、増援の気配を読んで備えられるかを評価する（E-39）。敵の能力・定義数・出現時機・AI は変えず、占有された増援の出現マスを近くの空きマスへ移す規則変更を反復 4 に含め（E-41）、難しいほうがよいという E-32 を守る。情報の追加による体感の難しさの変化は、遊んだ評価として記録する。

## 4. 作らないもの

- 新しい章・マップ・敵・仲間・クラス・スキル、能力・成長率・装備・敵の AI・難易度の調整
- 増援の定義の出現ターン・座標・人数・能力の変更、その番の増援を即行動させる変更。占有時の実出現位置は変更対象。候補がない場合の延期は行わない（決定（E-42））
- 正確な出現位置・時刻・人数の予告一覧、確率を新しく引く予兆、配置中の未出現増援の開示
- 巻き戻しの回数・単位・乱数・入口・保存・結果反映の規則の変更、未来への進み直し、プレビューからの行動
- 僧侶の絵の差し替え。騎兵用の CC0 素材の追加または自作は対象とするが、今回の文書修正では取得・作画しない（実装 Issue で管理役が担当）
- 大きなマップ・スクロール、錬金と品質、転職・支援、セーブ形式の変更
- JSON のキー・重複検証、Setup の Side 検証、移植用 API 全体の再設計、履歴上限の導入。性能測定から問題が出たら別に提案する

## 10. リスク

| 予兆が正確すぎる／弱すぎる | 領域と曖昧な文だけにし、H-14 の結果で評価する。能力などを一緒に調整しない |
| 絵柄の合う騎乗素材が見つからない | 実装 Issue で管理役が CC0 素材を探し、なければ 16×16 で自作する。97 で代用完了としない。README の 108 の説明は実際の緑のゴーストに直す申し送りとする（画像は差し替えない） |
| 増援をふさいだときの出現と難しさが伝わらない | ふさいでも近くに出ることに気付いたか、難しさを H-14 に記録する。距離 2 以内・候補なしなら不出現とする決定（E-42）に従い、予兆は代替位置も含める |
| プレビューの複製と全履歴で重くなる | 選択した 1 件だけを複製して再利用する。使用量・待ち時間を測り、履歴を黙って削らない |
| 未確認の合格扱い、レビュー・CI の抜け | 実装・自動・手動・遊んだ評価を分け、確認範囲と最新コミットの結果を記録する |
