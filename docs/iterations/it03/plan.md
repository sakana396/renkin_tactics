本書は反復の区切りの下書きで、実装の着手を認めるものではない。新しい要求 ID は SRS に足す案である。E-35・E-36 の要点と、9 章の補った点を人が確認したあと、SRS・ユースケース・既存設計の改訂を別に行う。既存の文書の決定事項は本書では変えない。

## 1. 目的

役割の尖りと今の難しさを保ちながら、ミスを巻き戻して動かし方を考え直せるようにする。あわせて、出撃前に場所を入れ替え、最初からキャラの強みを生かせるかを確かめる（E-35・E-36）。

## 2. 確かめたい仮説

| ID | 仮説 | 確かめ方 | 関連 |
|---|---|---|---|
| H-09 | 章ごとに 10 回の巻き戻しがあると、ミスのたびに章を最初からやり直さず、難しさを楽しみながら別の動かし方を試せる | 巻き戻した理由・戻した手数・変えた行動・その章の使用回数・章をやり直した回数を記録する。回数が足りたか、緊張が薄れたかも聞く | FR-BTL-09 案、E-32、E-35・E-36 |
| H-10 | 出撃前に場所を入れ替えられると、役割を考えて最初の配置を選べ、準備の操作でも迷わない | どのユニットをどこへ移し、最初の動きにどう効いたかを記録する。配置・準備への戻り・戦闘開始を迷わず選べたかを聞く | FR-CMP-11 案、FR-UNT-03、E-35 |
| H-11 | 自軍・敵軍の行動を一つの一覧で選べると、戻る場所と消費する回数を取り違えない | 自軍の行動前、敵軍の途中、主人公が倒れる前を選び、意図した状態かを聞く。1 回で何手戻したかと残り回数の理解を記録する | FR-BTL-09 案、IF-01、E-36 |

## 9. 確認したい点

ID は本書と DES-IT03 で共通に使う。**以下はすべて確認待ち**である。推奨を本文の案に使っただけで、承認済みの決定ではない。

| # | 点 | 推奨の案 | 理由・ほかの案 |
|---|---|---|---|
| Q-IT03-01 | E-35・E-36 の要点の文面 | 発言と説明文から補った点を分けた今回の文面を採る | 「まぁいらないかも」を断定せず、乱数や画面の規則を発言に足さない |
| Q-IT03-02 | 新しい要求 ID と優先度 | 巻き戻しを FR-BTL-09、配置を FR-CMP-11、どちらも M、検証は T・D とする | SRS の次の空き番号を使う。旧 FR-BTL-09（出来事の記録）は要求から外した番号なので、再利用の可否を確認する。再利用を避けるなら FR-BTL-10 として関連 ID を一括で変える |
| Q-IT03-03 | 僧侶の絵 | 差し替えは反復 3 に入れない | 見分けられたとの評価と「いらないかも」に沿い、中心の二つの機能に絞る。絵が不要という意味なら再確認する |
| Q-IT03-04 | 巻き戻す単位・乱数・敵軍の再開 | 移動と行動と反撃・追撃・経験・成長を 1 手とする。乱数も戻し、同じ状態で同じ行動なら同じ結果にする。敵軍の行動前に戻ったら、再開ボタンで残りの敵軍を自動で進める | 行動順や位置を考え直す救済にする。依頼にある天刻の拍動の「同じ行動でも別の結果になりうる」扱いとは差がある。巻き戻し回数を含む入力から別の乱数列を決める案も再現性を保てるが、今回は採らない。敵軍の途中だけ戻して同じ進行を再開すると結果も同じになる制限を明示する |
| Q-IT03-05 | 回数・章の再開・セーブ | 何手戻しても成功 1 回につき 1 消費。取消しと失敗は消費しない。戦闘を作ると 10 回、章のやり直しとロードでも 10 回。履歴・残り回数は保存しない | 今の章の始めだけのセーブと合う。巻き戻しで回数を取り戻すことはできない。章をやり直しても消費を残すならセーブ方針の変更が要る |
| Q-IT03-06 | 使える時機と消す未来 | 通常の入力待ち、再生中（再生を一時停止）、戦闘終了の帯と敗北の選択から開く。名簿へ結果を反映する前まで。戻した先以降の履歴を捨てる。番の開始処理も一覧で戻せる | ミスや主人公の敗北を救い、反映後の報酬・セーブを戻す複雑さを避ける。攻撃の途中には戻さない。再生中は表示した地点より先の履歴を見せない |
| Q-IT03-07 | 配置の範囲・主人公・操作 | 準備の次に配置を置く。出撃のマス内だけで 2 体を交換し、空いた出撃のマスへも動かせる。主人公も動かせる。準備に戻ると配置は初期化する | 少人数の出撃でも場所を選べる。主人公の出撃必須と名簿への対応は保ち、枠の 1 番目固定だけを見直す。初めの敵と地形も見せ、配置を考えられるようにする（DES-IT03 7.2 節） |
| Q-IT03-08 | 小さな課題の同梱 | 既存動作の文書化（出来事の定数名・Amount・回数 0 の表示）と REV-033 I-01 の手動ケースだけを入れる。JSON のキー検証と Side の検証は別 Issue に残す | 文書の整合と確認漏れを埋める。規則や保存の読み方の変更を同時に増やさない。既存設計への追記も人の承認後に別に行う |
| Q-IT03-09 | Linux の手動確認 | 反復 3 の遊びの確認に TC-NFR-03-04 を入れる。実施できなければ未実施の理由を残し、反復全体の完了の扱いを人が判断する | E-23 は反復 1 から外す判断で、恒久的な免除ではない。CI だけで NFR-03 の実演済みとはしない |
| Q-IT03-10 | H-04 と ADR-0002 | 境界を保ち、見直し案は移植前の別作業にする | 巻き戻しと配置に不要な拡張を入れない。反復 3 で増えた API と履歴の使用量は振り返りに記録する |
| Q-IT03-11 | 履歴の持ち方・保持範囲 | 行動前の状態の深い写しを、その戦闘の最初から保持する。敵軍の進行位置と PCG の内部状態も写す | 初期状態と行動列からの再実行より敵軍の途中への復帰を扱いやすい。記憶量は増えるので実測し、不足なら承認を経て再設計する。黙って古い行動を消さない |
