## 1. 目的

1. **文書を本線にそろえる**: 企画書・計画書・SRS・ユースケースを新作に合わせて改訂し、試作ブランチの設計メモを承認して正式な設計書にする。ふしぎ錬金に戦闘を戻す目的（E-02）は残す（E-130）
2. **試作ブランチの仕組みを main に入れる**: まとまりごとの PR に分け、それぞれ承認された文書を根拠にする（E-130）。キャラ・兵種・武器・アイテム・地形の定義は仮として使う。試作の 2〜3 章は取らず、試作の 1 章だけを作り直すまでの仮の章として置く（E-131・E-132）
3. **1〜3 章を作り直して遊べる形にする**: マップと配置を設計から作り直し（旧作と同じく制作記録を残す）、会話・絵・音・準備の画面をそろえ、新規から 3 章の終わりまで通しで遊べるようにする
4. **Claude が画像を生成できる環境を作る**: 手元の Codex CLI の画像生成（`image_generation`。ChatGPT のサブスクリプションの枠を使い、API キーは要らない）を Claude から呼ぶ道具を作り、指示文の組み立て → 生成 → 透過・縮小 → 台帳（`ASSETS.md`）への記入を Claude が回せるようにする（E-131・E-133）
5. **錬金の仕組みを広げる**: 錬金アイテムの種類（7 章 A）と章の間の調合（7 章 B）を、企画の軸「錬金術師は後衛で、前衛に守られながら強い道具を使う」（CON-DRAFT-NG01 1 章）に沿って足す（E-132）
6. **反復 7 の持ち越しを片付ける**: #190 の案 B の採用（E-132）と H-28・H-29（E-128）
