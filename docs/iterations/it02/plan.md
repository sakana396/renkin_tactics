章立てで進みながらキャラが育つことで、「キャラの強みを見つける」楽しさ（E-03）が反復 1 より増すかを確かめる。あわせて、倒れた仲間の扱い（離脱・ロスト）の緊張と、章の前後の短い物語・仲間の加入が、戦闘の舞台として効くかを確かめる（E-26）。

## 7. 進め方

1. 本計画書・設計書・ユースケースの下書きを書き、spec-reviewer がレビューする
2. 開発者が、9.2 節の点をまとめて一度に確かめる（E-26）。承認を受けてマージする
3. 設計書 9 章の案をもとに GitHub Issue（ラベル `it02`、マイルストーン `IT02`）を切る。Issue には依存と完了条件を書く
4. 実装は、Claude Code が管理役になり、サブエージェントが行う（E-27）。実装の割り振り（Codex かサブエージェントか）と Issue の着手は Claude Code が判断する。Codex の利用枠が戻れば、管理役が判断して Codex を使ってよい（E-14・E-20・E-27）。Issue ごとのプルリクエストを spec-reviewer でレビューし、自動マージの条件を満たせばマージする
5. 開発者が、反復 1 の版（`git checkout it01-play`）と反復 2 の版を遊び比べる（E-25）。反復 2 の版は、離脱とロストの両方で遊ぶ
6. 反復 1 の振り返り（H-01〜H-04）と、反復 2 の振り返り（H-05〜H-08）を書く
7. 振り返りを受けて SRS を更新する（TBD-01・04・06・10 の状態、FR-CMP-03 の「装備を選ぶ」の扱いなど）
