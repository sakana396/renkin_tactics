# 設計メモ（新作の試作 NG04: 高解像度の表示）

- 文書 ID: DES-NG04（設計要素の ID は DES-NG-10）
- 版: 0.2（**未承認**。エージェントが仕様の指示に沿って書いた設計メモ。フェーズ 1 に、8 章（フェーズ 2: 仮の地形と印・棒の比例）を足した）
- 作成日: 2026-11-13
- 対象: 新作（`-game alchemy`）の盤面を、ドット表示（1 マス 32 px）から **1 マス 48 px の高解像度表示**に変える土台
- 入力: DES-UI-01（画面の構成）、DES-UI-02（行動の一覧）、DES-UI-21（巻き戻し）、DES-UI-25（カメラ）、DES-UI-28（ミニマップ）、DES-UI-30（全体図）、DES-UI-31（予測窓・詳しい画面）、DES-NG-08（画像の差し込み）

**この文書は承認済みの SRS・設計書・企画書、`data/base`、既存の design-ng0x 文書を変更しない。** 承認を得るまで、ここに書いたことは「案」である。
既存の作品（`-game base`）は今までどおり 1 マス 32 px・窓 832×576 のままにする。`internal/core`・`internal/core/tactics` には何も足さない。

## 1. 目的と範囲

新作の盤面を、タイルを 2 倍にしたドット表示から、1 マス 48 px の高解像度表示へ移す。地形をなめらかな絵で描くのは次のフェーズ（フェーズ 2）で、このフェーズでは**マスの大きさを実行時に切り替えられるようにし、48 px で画面全体の配置が成り立つ**ところまでを作る。

作る: マスの大きさの切り替え（`Config.HiRes`）、48 px のときの配置、ドット絵のタイルの整数倍（3 倍）での描画、テストと文書。

範囲外（作らない）: 地形のなめらかな描画（フェーズ 2）、文字の大きさの変更、印・棒のデザインの作り直し、物語・準備・タイトルのデザインの作り直し、既存の作品の表示の変更。

## 2. 切り替えの仕組み

`internal/ui/layout.go` に置く。

| 名前 | 既定 | 高解像度 | 備考 |
|---|---|---|---|
| `CellSize`（変数） | 32 | 48 | 1 マスの大きさ |
| `MapSize`（変数） | 512 | 768 | `16 * CellSize`。盤面の表示範囲は常に 16×16 マス |
| `ScreenWidth`（変数） | 832 | 1088 | `MapSize + InfoWidth` |
| `ScreenHeight`（変数） | 576 | 832 | `MapSize + GuideHeight` |
| `InfoWidth`・`InfoHeight`・`GuideHeight`（定数） | 320・360・64 | 同じ | 右の情報欄と下の案内欄の大きさは変えない（文字の大きさが同じなので） |

- `ui.Config` に `HiRes bool` を足す（`Config` の変更はこの 1 項目だけ）。`Run` と `RunShot` は、窓を作る前に `useConfigMetrics(cfg)` を呼ぶ。`HiRes` が真なら 1 マス 48 px、偽なら 32 px にする（偽のときも明示的に既定へ戻す）。
- 切り替えは `useMetrics(cell)` の 1 か所にまとめる。`useMetrics` は上の 4 つの変数を更新し、次の節の `recomputeMetrics` を呼ぶ。
- 盤面の大きさに従う配置の値（右欄の中のボタンの位置、予測窓の候補、ミニマップの本体の位置など）は、`recomputeMetrics` が一括で作る。パッケージの `init` でも 1 回呼ぶので、既定の値は今までの定数と同じ（TC-DES-NG-10-01 で確かめる）。盤面の大きさに従う値を足すときは、ここに足す。
- グローバルな状態なので、起動時に 1 回だけ切り替える。テストでは `useTestMetrics`（`t.Cleanup` で既定へ戻す）を使い、`t.Parallel` を使わない。
- `cmd/renkin` は、`-game alchemy` のときだけ `HiRes: true` を渡す（TC-DES-NG-10-17）。

## 3. 48 px のときの配置

```
x: 0              768                 1088
y=0   ┌──────────────┬──────────────────┐
      │ 盤面 768×768 │ 情報欄 320×360   │
      │（16×16 マス）├──────────────────┤ y=360
      │              │ ミニマップの欄    │
      │              │ 320×408          │
y=768 ├──────────────┴──────────────────┤
      │ 案内欄（高さ 64）                │
y=832 └─────────────────────────────────┘
```

- 盤面は 768×768。右の情報欄は幅 320・高さ 360 で、x = 768 から。その下の y = 360〜767 をミニマップの欄とする（高さは盤面の高さまで伸ばす）。ミニマップの本体（128×128）と文・ボタンは、欄の左上から今と同じ相対位置に置く（余白が増える）。
- 下の案内欄は高さ 64 で、y = 768 から。窓は 1088×832。
- **右欄の x** は盤面の幅に従う（既定の x = 512 を `MapSize` に結び付ける）。**案内欄の y** も同じく `MapSize` から数える。右欄の中の y（情報欄 y < 360、ミニマップの欄の中）は変えない。右欄・案内欄に置くものは、既定の位置から `boardShift()`（= `MapSize − 512`。既定は 0、48 px では 256）だけずらす。

## 4. 盤面を持たない場面

タイトル・ルール選択・物語・仲間の加入・準備・勝利の結果・クリアは、832×576 を前提に配置している（準備は特に細かい）。**デザインは作り直さず**、この配置を窓の**中央**に置く。

- 配置の大きさは定数 `sceneCanvasWidth × sceneCanvasHeight`（832×576。`sceneOffset()` が窓の中央へ置く左上の位置を返す。既定では (0, 0)、高解像度では (128, 128)）。物語の文の折り返し・肖像の配置は、窓の幅ではなく、この幅に従う。
- 描画（`drawScene`）: 高解像度のときだけ、背景（場面の背景画像と暗い膜）は窓の全体に描き、そのほかを 832×576 の層に描いて窓の中央へ重ねる。既定の表示では今までと同じ経路（層を使わない）。
- 入力（`Game.cursor`）: 同じ場面では、カーソルの位置から `sceneOffset()` を引いて場面へ渡す。
- 盤面を持つ場面（戦闘・敗北・配置）は窓の全体を使い、中央寄せしない。場面の絵（加入した仲間のタイル）は、倍率に関係なく 32 px で描く。
- 詳しい画面（DES-UI-31）は、既定の幅の配置を横方向だけ中央へ寄せる。

## 5. ドット絵のタイルの描画

- `drawTile` の倍率は `CellSize / 16`（整数。32 なら 2 倍、48 なら 3 倍）。最近傍法のまま（Ebitengine の既定のフィルタ）。地形・ユニットの代用タイルはマスの大きさに合わせて描かれる。
- 下地・ボスの枠・範囲の塗り・選択の枠は `CellSize` から描く。
- 画像で差し込んだユニットの絵は、`unitArtRect` が `CellSize` に収める（変更なし。TC-DES-NG-10-10）。
- HP の棒・装備の印・指揮の印・ピン・ZOC の角印・ボスの ★ は、**px の大きさを変えず**、マスの隅の位置（`CellSize` からの相対）だけを結び付ける。48 のマスでは相対的に小さくなるが、重ならない（TC-DES-NG-10-11）。見た目の調整は、地形・ユニットの絵が決まるフェーズ 2 以降で行う。

## 6. 設計への提案（人の承認を待つ）

1. 盤面を持たない場面を、デザインを作り直さず窓の中央に置く（四方に 128 px の余白）。窓いっぱいに広げる配置は、フェーズ 2 以降で検討する。
2. 印・棒の大きさは 48 px でも変えない。
3. 巻き戻しの確認や予測窓など、盤面の四隅の 416×240 の窓は大きさを変えない（768 の盤面の四隅に置く。中央には隙間ができる）。
4. 文字は今のフォントの大きさのままにする（指示どおり）。48 px でも読めるが、情報欄は 320 px 幅のままなので相対的に小さい。

## 7. 確認していないこと

- 実際の窓での操作感（カーソルの位置の補正を含む。`Game.cursor` は Ebitengine の窓がないとテストできない）は、人が確かめていない。
- 画像で差し込んだユニットの絵を 48 px で見たときの見た目。
- 予測窓・全体図を、16 マスを超える大きな盤面で 48 px 表示した画面。配置の数値はテストで確かめた。

## 8. フェーズ 2: なめらかな仮の地形と、印・棒の比例（DES-NG-10）

フェーズ 1 の 5 章で「ドット絵のタイルの 3 倍」にした地形は、ユニットのなめらかな絵（`art/units/aoi.png`）と絵柄が合わない。高解像度の表示（`Config.HiRes`）の新作だけ、地形をコードで描いたなめらかな**仮の絵**にし、あとから AI 生成の絵へ差し替える口を作る。既存の作品（HiRes が偽）の見た目・動作は変えない。仮の絵の方針は [new-game-visual-draft.md](../01_concept/new-game-visual-draft.md) 2.1〜2.2 節（全体に低彩度、鮮やかなのは水の青緑と琥珀だけ、石は乾いた砂色）に従う。

### 8.1 仮の地形の画像（`internal/ui/terrain_art.go`）

`terrainPlaceholder(id, variant)` は、地形の ID と変種の番号（0〜3）から **48×48 の不透明な `*image.RGBA`** を返す純粋な関数（Ebitengine を使わない）。

- **なめらかさ**: 96×96 で描き、2×2 の平均で 48 に縮める。
- **決定的**: 乱数は、ID と変種の番号のハッシュを種にした自前の擬似乱数（splitmix64）。グローバルな乱数を使わず、毎回同じ画像になる。
- **変種**: 1 つの地形に 4 枚。`terrainVariantIndex(x, y, n)`（マスの座標のハッシュ）で選ぶので、同じマスはいつも同じ変種で、同じ地形が並んでも模様が繰り返されにくい。
- **継ぎ目**: 石畳は 2 段の敷石で、目地を縁に半分ずつ置く（隣のマスと合わせて 1 本になる）。石を縁でまたがせない。
- 画像は、起動後に最初に引いたとき 1 回だけ `ebiten.Image` にして覚える（`ArtStore.terrainSetOf`）。毎フレーム作らない。

| 地形（ID） | 描くもの |
|---|---|
| 石畳（plain） | 砂色の敷石。目地、石ごとの明るさの差、小さな欠けとしみ。平地として下地だけ |
| 瓦礫（rubble） | 石畳の上に、灰褐色の割れた石の塊（影付き）と砂利 |
| 植え込み（bush） | 石畳の上に、低彩度の緑の丸い茂み（複数の円を重ね、影付き） |
| 崩れた壁（wall） | 太い砂色の石ブロックの壁。上辺がぎざぎざに欠け、上面は明るく前面は暗く、足元に影。通れない見た目 |
| 水路（canal） | 青緑の水に明るい波の線。四辺を石の縁取りで囲む。通れない見た目 |
| 浄水施設（facility） | 石の台の上に、青緑に光る円環、線と円の記号（三角形と頂点の円。1 つだけ琥珀）、中心の淡い光 |

### 8.2 描画の経路（`internal/ui/game.go`、`terrain_store.go`）

`drawTerrainCell` が、戦闘・巻き戻しの下見（`drawBoardTerrain`）と配置（`drawDeploy`）で共通に地形を描く。

1. HiRes で、地形の**名前**（`tactics.Terrain.Name`。tactics は ID を知らない）が目録（`defs.Catalog`）の地形の名前に当たり、その ID の絵（差し替えの PNG か仮の絵）があれば、その絵だけで 1 マスを埋める。草の下地（`assets.Grass`）は描かない。
2. それ以外（HiRes でない・既存の地形名・知らない地形）は、今までの経路（草の下地に、ドット絵のタイルを `CellSize/16` 倍で重ねる）。
3. 名前から ID を引く表は、キャラ名→キャラ ID（DES-NG-08）と同じ作りで `artIndex` に持つ。全体図（`drawOverview`）とミニマップは今までの描き方のまま（範囲外）。

### 8.3 AI 生成の地形の差し替え口

`data/alchemy/media/art/terrain/<地形の ID>.png`（例: `terrain/canal.png`）。**正方形の PNG（推奨 192×192、一辺 4096 まで、不透明）**。あれば、仮の絵の代わりにマスの大きさへ拡大縮小して描く。

- 変種: `terrain/<ID>_2.png`〜`_4.png`。**あるものだけ**をマスのハッシュで選ぶ（`<ID>.png` がなくても `_2` だけで使える）。
- 1 枚でも PNG があれば、その地形は PNG だけを使い、仮の絵は混ぜない。1 枚もなければ仮の絵。
- 読み込みの誤り・大きさの上限（一辺 4096）・壊れた PNG・正方形でない画像は、既存の `ArtStore` の仕組み（同じ画像につき 1 回だけ stderr に出し、「なし」として扱う。正方形でないものは知らせて使う）に従う。
- 名前の規則: `data/media_ledger.go` の `artNameRule` に `terrain/[a-z0-9_]+\.png` を足した。台帳（ASSETS.md）に出典を書く規則は、ほかの画像と同じ。
- 目録にない地形名の PNG は引けない（ID を目録から作るため）。

### 8.4 印・棒の大きさ（`scaled`）

フェーズ 1 では、HP の棒・装備の印・指揮の印・固定のピンなどを 32 px 用の px のままにして、48 px では相対的に小さかった。`scaled(n) = n * CellSize / 32`（端数は切り捨て）で比例させる。既定（32）では恒等で、見た目・テストは変わらない。

| 部品 | 32 px | 48 px | 備考 |
|---|---|---|---|
| 装備の印の一辺 | 10 | 15 | `equipMarkSize`（`EquipMarkSize` は 32 での値として残す） |
| HP の棒の太さ（左の余白、下の余白） | 4（2、1） | 6（3、1） | 右端は装備の印の 1 px 手前 |
| 指揮の印の箱（盤面） | 12 | 18 | 右欄の印（`commandMarkSize`）は変えない |
| 固定のピン（頭、軸） | 6×6、2×4 | 9×9、3×6 | ボスは ★（文字は変えない 12 px）の左 |
| ZOC の角印（余白、腕、線の太さ） | 5、5、2 | 7、7、3 | 敵軍の角印の y は `CellSize − scaled(8)`（HP の棒の上） |
| ボスの枠・★ | 2 | 3 | ★ の文字の大きさは変えない |

重ならないこと（装備の印と棒、指揮の印とピン、敵軍の角印と棒）は、32・48・64 で TC-DES-NG-10-28 が確かめる。フェーズ 1 の TC-DES-NG-10-11 は、この比例後の値（装備の印 15、棒の太さ 6、右端 32、敵軍の角印 y = 36）に更新した。

### 8.5 設計への提案（人の承認を待つ）

1. 水路は、四辺に縁取りがあるので、続いた水路は「水の四角が並ぶ」見た目になる（隣のマスの種類を見ない仕組みのため）。続いて見せるには、隣のマスの地形を引き数に足す必要がある。AI 生成の絵に差し替えるときの割り切りとして、今は足さない。
2. 全体図・ミニマップは、ドット絵の色のままにする。
3. 仮の絵を作る関数は `internal/ui` に置く（画像を作るだけで、描画はしない）。AI の絵がそろったら、この関数ごと消してよい。

### 8.6 確認していないこと

- 実際の窓での見た目。`RunShot` で撮った画像（ch01〜ch03）を、エージェントが目で見て確かめた。
- AI 生成の地形の PNG を実際に置いたときの見た目（まだ絵がない）。PNG の差し替えの仕組みは、テストの合成の PNG で確かめた。
