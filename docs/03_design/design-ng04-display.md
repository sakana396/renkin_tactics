# 設計メモ（新作の試作 NG04: 高解像度の表示）

- 文書 ID: DES-NG04（設計要素の ID は DES-NG-10）
- 版: 0.1（**未承認**。エージェントが仕様の指示に沿って書いた設計メモ。フェーズ 1 の分）
- 作成日: 2026-11-13
- 対象: 新作（`-game alchemy`）の盤面を、ドット表示（1 マス 32 px）から **1 マス 48 px の高解像度表示**に変える土台
- 入力: DES-UI-01（画面の構成）、DES-UI-02（行動の一覧）、DES-UI-21（巻き戻し）、DES-UI-25（カメラ）、DES-UI-28（ミニマップ）、DES-UI-30（全体図）、DES-UI-31（予測窓・詳しい画面）、DES-NG-08（画像の差し込み）

**この文書は承認済みの SRS・設計書・企画書、`data/base`、既存の design-ng0x 文書を変更しない。** 承認を得るまで、ここに書いたことは「案」である。
既存の作品（`-game base`）は今までどおり 1 マス 32 px・窓 832×576 のままにする。`internal/core`・`internal/core/tactics` には何も足さない。

## 1. 目的と範囲

新作の盤面を、タイルを 2 倍にしたドット表示から、1 マス 48 px の高解像度表示へ移す。地形をなめらかな絵で描くのは次のフェーズ（フェーズ 2）で、このフェーズでは**マスの大きさを実行時に切り替えられるようにし、48 px で画面全体の配置が成り立つ**ところまでを作る。

作る: マスの大きさの切り替え（`Config.HiRes`）、48 px のときの配置、ドット絵のタイルの整数倍（3 倍）での描画、テストと文書。

範囲外（作らない）: 地形のなめらかな描画（フェーズ 2）、文字の大きさの変更、印・棒のデザインの作り直し、物語・準備・タイトルのデザインの作り直し、既存の作品の表示の変更。

## 2. 切り替えの仕組み

`internal/ui/layout.go` に置く。

| 名前 | 既定 | 高解像度 | 備考 |
|---|---|---|---|
| `CellSize`（変数） | 32 | 48 | 1 マスの大きさ |
| `MapSize`（変数） | 512 | 768 | `16 * CellSize`。盤面の表示範囲は常に 16×16 マス |
| `ScreenWidth`（変数） | 832 | 1088 | `MapSize + InfoWidth` |
| `ScreenHeight`（変数） | 576 | 832 | `MapSize + GuideHeight` |
| `InfoWidth`・`InfoHeight`・`GuideHeight`（定数） | 320・360・64 | 同じ | 右の情報欄と下の案内欄の大きさは変えない（文字の大きさが同じなので） |

- `ui.Config` に `HiRes bool` を足す（`Config` の変更はこの 1 項目だけ）。`Run` と `RunShot` は、窓を作る前に `useConfigMetrics(cfg)` を呼ぶ。`HiRes` が真なら 1 マス 48 px、偽なら 32 px にする（偽のときも明示的に既定へ戻す）。
- 切り替えは `useMetrics(cell)` の 1 か所にまとめる。`useMetrics` は上の 4 つの変数を更新し、次の節の `recomputeMetrics` を呼ぶ。
- 盤面の大きさに従う配置の値（右欄の中のボタンの位置、予測窓の候補、ミニマップの本体の位置など）は、`recomputeMetrics` が一括で作る。パッケージの `init` でも 1 回呼ぶので、既定の値は今までの定数と同じ（TC-DES-NG-10-01 で確かめる）。盤面の大きさに従う値を足すときは、ここに足す。
- グローバルな状態なので、起動時に 1 回だけ切り替える。テストでは `useTestMetrics`（`t.Cleanup` で既定へ戻す）を使い、`t.Parallel` を使わない。
- `cmd/renkin` は、`-game alchemy` のときだけ `HiRes: true` を渡す（TC-DES-NG-10-17）。

## 3. 48 px のときの配置

```
x: 0              768                 1088
y=0   ┌──────────────┬──────────────────┐
      │ 盤面 768×768 │ 情報欄 320×360   │
      │（16×16 マス）├──────────────────┤ y=360
      │              │ ミニマップの欄    │
      │              │ 320×408          │
y=768 ├──────────────┴──────────────────┤
      │ 案内欄（高さ 64）                │
y=832 └─────────────────────────────────┘
```

- 盤面は 768×768。右の情報欄は幅 320・高さ 360 で、x = 768 から。その下の y = 360〜767 をミニマップの欄とする（高さは盤面の高さまで伸ばす）。ミニマップの本体（128×128）と文・ボタンは、欄の左上から今と同じ相対位置に置く（余白が増える）。
- 下の案内欄は高さ 64 で、y = 768 から。窓は 1088×832。
- **右欄の x** は盤面の幅に従う（既定の x = 512 を `MapSize` に結び付ける）。**案内欄の y** も同じく `MapSize` から数える。右欄の中の y（情報欄 y < 360、ミニマップの欄の中）は変えない。右欄・案内欄に置くものは、既定の位置から `boardShift()`（= `MapSize − 512`。既定は 0、48 px では 256）だけずらす。

## 4. 盤面を持たない場面

タイトル・ルール選択・物語・仲間の加入・準備・勝利の結果・クリアは、832×576 を前提に配置している（準備は特に細かい）。**デザインは作り直さず**、この配置を窓の**中央**に置く。

- 配置の大きさは定数 `sceneCanvasWidth × sceneCanvasHeight`（832×576。`sceneOffset()` が窓の中央へ置く左上の位置を返す。既定では (0, 0)、高解像度では (128, 128)）。物語の文の折り返し・肖像の配置は、窓の幅ではなく、この幅に従う。
- 描画（`drawScene`）: 高解像度のときだけ、背景（場面の背景画像と暗い膜）は窓の全体に描き、そのほかを 832×576 の層に描いて窓の中央へ重ねる。既定の表示では今までと同じ経路（層を使わない）。
- 入力（`Game.cursor`）: 同じ場面では、カーソルの位置から `sceneOffset()` を引いて場面へ渡す。
- 盤面を持つ場面（戦闘・敗北・配置）は窓の全体を使い、中央寄せしない。場面の絵（加入した仲間のタイル）は、倍率に関係なく 32 px で描く。
- 詳しい画面（DES-UI-31）は、既定の幅の配置を横方向だけ中央へ寄せる。

## 5. ドット絵のタイルの描画

- `drawTile` の倍率は `CellSize / 16`（整数。32 なら 2 倍、48 なら 3 倍）。最近傍法のまま（Ebitengine の既定のフィルタ）。地形・ユニットの代用タイルはマスの大きさに合わせて描かれる。
- 下地・ボスの枠・範囲の塗り・選択の枠は `CellSize` から描く。
- 画像で差し込んだユニットの絵は、`unitArtRect` が `CellSize` に収める（変更なし。TC-DES-NG-10-10）。
- HP の棒・装備の印・指揮の印・ピン・ZOC の角印・ボスの ★ は、**px の大きさを変えず**、マスの隅の位置（`CellSize` からの相対）だけを結び付ける。48 のマスでは相対的に小さくなるが、重ならない（TC-DES-NG-10-11）。見た目の調整は、地形・ユニットの絵が決まるフェーズ 2 以降で行う。

## 6. 設計への提案（人の承認を待つ）

1. 盤面を持たない場面を、デザインを作り直さず窓の中央に置く（四方に 128 px の余白）。窓いっぱいに広げる配置は、フェーズ 2 以降で検討する。
2. 印・棒の大きさは 48 px でも変えない。
3. 巻き戻しの確認や予測窓など、盤面の四隅の 416×240 の窓は大きさを変えない（768 の盤面の四隅に置く。中央には隙間ができる）。
4. 文字は今のフォントの大きさのままにする（指示どおり）。48 px でも読めるが、情報欄は 320 px 幅のままなので相対的に小さい。

## 7. 確認していないこと

- 実際の窓での操作感（カーソルの位置の補正を含む。`Game.cursor` は Ebitengine の窓がないとテストできない）は、人が確かめていない。
- 画像で差し込んだユニットの絵を 48 px で見たときの見た目。
- 予測窓・全体図を、16 マスを超える大きな盤面で 48 px 表示した画面。配置の数値はテストで確かめた。
