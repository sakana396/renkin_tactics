- 作成日: 2026-11-13
- 対象: 新作（`-game alchemy`）の画面に、AI 生成などの画像を、コードを変えずに差し込む仕組み

## 1. 目的と範囲

画像そのものはこの文書の範囲外（開発者が AI などで作って置く）。ここで作るのは、置いた画像が**コードを変えずに画面に出る**こと、
**置いていない画像は今の見た目のまま**であること、**置いた画像の出典と利用条件が必ず記録される**ことの 3 つ。

範囲外（作らない）: 画像の生成、地形タイルの差し替え、アニメーション、既存の作品（`-game base`）の見た目の変更、`core`・`tactics` の変更（ADR-0002）。

## 3. 置き場と名前の規則

すべて `data/alchemy/media/art/` の下。PNG（透過可）。ファイルがなければ今の見た目のまま。大きさは**一辺が 4096 px 以下**ならよい（下の推奨は、AI 生成の依頼の目安。推奨の大きさでなくても使える）。4096 を超える画像は「使えない画像」として扱う（4.1 節）。

| 用途 | ファイル | 推奨の大きさ | 使い方 |
|---|---|---|---|
| 自軍のユニット | `units/<キャラの ID>.png`（例: `units/aoi.png`） | 128×128 | 盤面のマス（32 px）に縮めて描く。陣営の下地（青）の上に重ねる。キャラの絵が**最優先**、なければ今のタイル |
| 敵のユニット | `units/enemy_<クラスの ID>.png`（例: `units/enemy_bandit.png`） | 128×128 | 同上。下地は赤。敵のボスの金の枠・HP の棒・印は今のまま |
| 人物の絵（肖像） | `portraits/<キャラの ID>.png` | 512×512 | 物語の段落の話者の絵（4 章）。ユニット情報の画面（64 px の枠）にも出す |
| 場面の背景 | `story/<物語の ID>.png`（例: `story/ch01_before.png`） | 832×576（画面と同じ） | 物語の場面の背景。暗い膜（黒・不透明度 63%）を重ねて文字を読めるようにする |
| タイトルの背景 | `title.png` | 832×576 | タイトル画面の背景。同じ暗い膜を重ねる |

- ID は `data/alchemy/characters.toml`・`classes.toml`・`story.toml` の `id`。画面に出る名前（キャラの `name`、クラスの `name`）から ID を引く表を、起動時に目録から作る（同じ名前が重なったら ID の昇順で先のもの。`defs.Catalog` に `Characters()`・`Classes()` を足した）
- ユニットの絵は、`tactics.Unit` の名前・クラス名・陣営だけから引く（`ArtKey`）。`core`・`tactics` には何も足さない
- 正方形でない画像は使える。縦横比を保って、マスや枠に収めて中央に置く（読み込み時に stderr へ 1 回知らせる）。背景は正方形を期待しない。画面を隙間なく覆うよう拡大し、はみ出しは中央で切る

## 4. 振る舞い

### 4.1 読み込み（`ArtStore`）

- `media`（`fs.FS`）の下の PNG を、初めて引いたときに読み、結果（なしを含む）を覚える。描画用の `ebiten.Image` は読んだときに 1 回だけ作り、元の `image.Image` は持ち続けない（`ebiten.Image` だけを覚える）
- ない（`fs.ErrNotExist`）: 「なし」。何も出さない
- 壊れている（PNG として読めない・大きさが 0・開けない）: 「なし」として扱い、誤りを stderr に 1 回だけ出す。ゲームは止めない
- 一辺が 4096 px を超える画像（`artMaxSide`）: 使えない画像として「なし」にし、「画像が大きすぎます」を stderr に 1 回だけ出す。大きさを先に調べ（`png.DecodeConfig`）、超えるものは展開しない。Ebitengine の画像の置き場（atlas）に載せられず、載せようとすると panic になるため。4096 ちょうどは使える
- `Config.Media` が nil（`-game base`）: すべて「なし」。ファイルを読みにいかない。既存の作品の表示は変わらない
- `Config.Stderr` が nil なら `os.Stderr`。`Config` は変えていない

### 4.2 物語の場面

- 話者: 段落が「名前「…」」の形のとき、その名前。先頭から最初の「「」までを名前とし、前後の空白（半角・全角）と、後ろの括弧書き（`アオイ（小声）「…」`）を除く。名前に句読点（。、，．）・！？・閉じ括弧・改行を含む、名前が空、名前が 12 文字を超える、閉じの「」」がない段落は、話者なし（地の文の途中の台詞を拾わないため）。台詞が 2 人分ある段落は、先頭の話者
- 話者の名前が目録のキャラ名と一致し、`portraits/<ID>.png` があるとき、その段落のあいだ肖像を出す。一致するキャラがいない（「役人」など）、絵がなければ出さない
- 肖像があるとき、本文は肖像の右（x = 296、幅 488）に折り返す。肖像の箱は x = 48、y = 120、224×224。肖像がなければ今の配置（x = 48、幅 736）のまま
- 背景は `story/<物語の ID>.png`（章の前の物語・後の物語の ID）。あれば全体に描き、暗い膜を重ねる。タイトルは `title.png`

### 4.3 盤面・情報欄

- 盤面（戦闘・配置）のユニット: 下地・ボスの枠を描いたあと、絵があれば絵を、なければ今のタイルを描く。自軍の行動済みの暗さも絵に適用する。HP の棒・指揮の印・装備の印は今のまま上に重なる
- 情報欄・詳細・戦闘の概要の 64 px の絵（`InfoIcon`）: 自軍は肖像、なければユニットの絵、なければタイル。敵はユニットの絵、なければタイル
- 全体図（`boardnav_draw.go`）の 16 px のタイルと、準備の名簿の小さな絵は、今のまま（画像を使わない）

### 4.4 描く位置と大きさ

見た目は目で確かめるため、位置と大きさは純粋な関数に分けた（`art_layout.go`）: `fitRect`（箱へ縦横比を保って収める）、`coverRect`（画面を覆う）、`storyArtLayout`（肖像の箱と本文の左端・幅）、`unitArtRect`（1 マスへ収める）。
`SceneView` に `Backdrop`（背景の道筋）と `Portrait`（肖像の道筋と箱）を足した。画像がないとき、この 2 つは空・nil で、文の配置も今のまま。

## 5. 台帳 `data/alchemy/media/ASSETS.md` と検査

画像と音のファイルの出典と利用条件を、1 ファイル 1 行の表で必ず残す。**音のファイル（`audio/` の下）も同じ表・同じ書き方**で管理する（音の担当は同じ表に行を足す）。

| 列 | 内容 |
|---|---|
| ファイル | `media` からの道筋を `` ` `` で囲む（例: `` `art/units/aoi.png` ``、`` `audio/se/bomb.wav` ``） |
| 作り方 | `AI 生成`・`自作`・`既存素材` のどれかで始める（例: `自作（tools/synth で合成）`） |
| 使ったツールと版・生成した日 | ツール名・モデル名・版と日付。自作の音は道具と版（コミット ID など） |
| 指示（プロンプト）または出典の URL | AI 生成は指示の全文、既存素材は入手した URL、自作は作り方の要点 |
| 利用条件 | ライセンス名や規約の該当箇所（商用利用・改変・表記の要否）。AI 生成はツールの規約が生成物の利用を許す根拠 |
| 確かめた日 | `YYYY-MM-DD` |
| 確かめた人 | 名前（開発者など） |

検査（`data.CheckMediaLedger`。`go test ./data` で実際の `data/alchemy/media` に適用する）:

1. `art/` と `audio/` の下のすべてのファイル（`README.md`・`ASSETS.md` を除く）が、台帳の「ファイル」欄にある
2. 台帳の各行のファイルが実在し、`art/` か `audio/` の下にある。道筋が正しい（`..` で外へ出ない）。同じファイルを 2 行に書かない
3. 必須の 7 欄が空でない（`-`・`なし`・`未定`・`不明`・`TBD` も空とみなす）
4. 「作り方」が 3 つのどれかで始まる。「確かめた日」が `YYYY-MM-DD`
5. 台帳がない・「ファイル」で始まる見出しの表がない場合も落ちる。` ``` ` の囲みの中（見本の行）は読まない

台帳に載らない画像をコミットすると、`go test ./...` が落ちる（CI でも落ちる）。

## 6. 試し用の絵と、画像を置いて試す手順

`go run ./tools/mkplaceholder [-out ./placeholder-out]` が、単色の人型のシルエットと名前の文字が入った仮の PNG を書き出す。

- 書き出すもの: 全キャラの `units/<ID>.png`（128×128）・`portraits/<ID>.png`（512×512）、全クラスの `units/enemy_<ID>.png`、全物語の `story/<ID>.png`、`title.png`（背景は 832×576）。出力先の中は `art/` の中身と同じ並び
- 出力先の既定は media の外（`./placeholder-out`）。`data/alchemy/media` の下は拒否する（終了コード 2）
- **この道具の作る画像は試すためだけで、台帳に載せず、コミットしない**（台帳の検査で落ちる）。既定の出力先 `placeholder-out` は `.gitignore` に入れてある。`media/art` へコピーした絵は無視されないので、コミットする前に `git status` で確かめること

手順（開発者が仕組みを試す）:

```sh
go run ./tools/mkplaceholder                    # ./placeholder-out に仮の絵ができる
mkdir -p data/alchemy/media/art
cp -r placeholder-out/* data/alchemy/media/art/ # 試したい絵だけコピーしてもよい
go run ./cmd/renkin -game alchemy               # 埋め込みは build のたびに更新される
# ... 確かめたら、コミットしない。消す
rm -r data/alchemy/media/art/units data/alchemy/media/art/portraits data/alchemy/media/art/story data/alchemy/media/art/title.png
```

本物の画像を置くとき: 3 章の名前で `data/alchemy/media/art/` に置き、`ASSETS.md` の表に 1 行ずつ書く（5 章）。コードの変更は要らない。

## 7. 判断した点・承認が要る点・未確認

| 項目 | この案での扱い | 理由・影響 |
|---|---|---|
| 画面への組み込み（`game.go`） | 反映済み。描く部品（`art_draw.go` の `drawUnitArt`・`drawInfoIcon`・`drawSceneBackdrop`・`drawScenePortrait`）を `game.go` の 4 か所から呼ぶ。戦闘の概要・詳細画面の絵の値は `battle_windows_it07.go`・`unit_detail_it07.go` が `InfoIcon.Art` に渡す | 画像を置くと画面に出る。実画面の確認は TC-DES-NG-08-94（手動・未実施） |
| `defs.Catalog` に `Characters()`・`Classes()` を足した | 追加のみ。既存の動作は変わらない | 画面の名前の対応と、試し用の絵の書き出しに、全件の一覧が要る |
| 非正方形の扱い | 使う（縦横比を保って収める）。stderr に 1 回知らせる | 禁止にもできる（その場合は「壊れた画像」と同じ扱いにする） |
| 同名のキャラ・クラス | ID の昇順で先のものに対応させる | 新作のデータに同名はない。重なると後のものの絵が出ない |
| 敵の絵はクラス単位 | 同じクラスの敵は同じ絵。ボスは金の枠で見分ける | 企画の「兵種ごとの絵」。個別の敵の絵が要るなら規則を足す |
| 画像の拡大縮小 | 線形補間（128 px → 32 px など）。ドット絵の拡大には向かない | AI 生成の絵を縮める前提 |
| 全体図・準備の名簿の絵 | 画像を使わない | 16 px 前後で絵が読めない。要望があれば足す |
| 見た目 | 目で確かめていない部分が残る（実際の画像での見え方、肖像と本文の釣り合い、暗い膜の濃さ） | 試し用の絵でタイトル画面の背景が出ることだけ、手元で確認した |
