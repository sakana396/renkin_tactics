## 1. 目的と範囲

- 新作（`-game alchemy`、`Config.HiRes`）の**準備画面**を、窓 1088×832 を使い切る、キャラを大きく見せるカード型に作り直す
- **既存の作品（`-game base`、HiRes が false）の準備画面は変えない**（今の配置・描画・操作・テストのまま）
- 直す課題: (1) 窓を使い切れていない、(2) 名簿の行が小さくて見づらい、(3) 詳細欄に空きが多く、肖像が小さい、(4) 持ち物の管理が分かりにくい（別のタブ、上限の 5 枠が見えない）、(5) 章の情報（目的・敵・武器の相性）が準備で分からない、(6) 世界観と見た目が合っていない
- 作らないもの: 配置画面（準備の次の画面）の作り直し、物語・戦闘の画面、スキルの新しい規則、UI の AI 生成素材（枠・背景。9 章の「素材」を参照。まずコードで描く）

## 3. 操作

- キャラの選択: ↑↓、またはカードのクリック（今の名簿と同じく、出撃・外すの切り替えは、カードの左端のチェック `[✓]` のクリック）
- 持ち物の受け渡し（今の「持ち物」タブをなくし、右の欄に統合する）:
  1. 在庫の行をクリックして選ぶ（選んだ行をアクアの枠）
  2. 手持ちの空き枠をクリックすると、在庫から渡す（1 個）
  3. 手持ちの枠をクリックすると、在庫に戻す
  4. 上限（5 枠）に達していたら、空き枠がないので渡せない。理由を案内欄に出す
- 武器の装備の切り替え: 手持ちの武器の枠を右クリックで、「装備」にする（今の「装備・スキル」タブの装備の切り替えを、この欄へ移す）。左クリックは「在庫に戻す」に割り当てるので、「選んだ状態でもう一度クリックで装備」は作らない。**今の操作が、準備画面のどこにあるかを、実装前に確かめて、失われないようにする**
- 「能力」と「装備・スキル」のタブ（Tab キー）は、中央のカードに、**両方を同時に出す**ので、なくす
- 「配置へ」: 今と同じ（ボタン）。Enter でも進める（下の「設計への提案」）
- 戻る操作は置かない（承認済みの E-124、DES-IT07 3.5 節「準備の画面からほかの画面へは戻らない」）。Esc・右クリックは、在庫の選択を外す（右クリックが手持ちの武器の枠の上なら、装備の切り替え）
- **設計への提案（未承認）**: ↑↓（キャラの選択）と Enter（配置へ）は、今の準備にはない。HiRes の準備にだけ新しく足す。承認されなければ外す（HiRes でない準備には足さない）

## 4. 章の情報の出どころ

- 章の名前: `ChapterDef.Name`
- 目的: **今の定義に、目的の文がない**（`ChapterDef` は ID・名前・マップ・物語・加入・報酬だけ）。案: `chapters.toml` に `goal`（任意の文字列）を足し、`defs.ChapterDef` と defload を直す（**定義の形式の変更。人の承認が要る**）。承認までは、勝利条件から決めた固定の文（「敵のボスを倒す」）を出す
- 敵: `MapDef.Enemies` の兵種（`class`）と武器（`weapon`）から、兵種ごとの数と武器の種類（剣・槍・斧・弓・魔法）を数える。ボスは名前付きで別の行。増援（`Reinforcements`）は「増援あり」と 1 行
- 武器の相性の早見: 規則（tactics の `triangle`）と同じ向き（槍 > 剣 > 斧 > 槍）を、画面側の表で持たず、`tactics` の規則から引く口を足す（画面で規則を計算し直さない）
- 在庫: `core` のキャンペーンの共有の在庫

## 5. 実装の進め方

1. **画面の値（View）を先に作る**: 準備の `SceneView`（今の `prepare.go`）に、HiRes 用の別の組み立て（`PrepareViewHiRes`）を足す。HiRes でないときは、今のまま。描画と入力の判定が同じ値を使う
2. 描画: 枠・パネル・棒をコードで描く（`vector` 描画）。肖像は `ArtStore.Shrunk` を使い、大きさごとに縮めたものを 1 回だけ作る
3. 入力: 今の準備の操作（`PrepareController` など）を壊さないよう、**操作の意味（選ぶ・出撃を切り替える・持ち物を渡す・戻す・装備を替える・配置へ）は変えず、座標の判定だけを新しい配置に合わせる**
4. 試験: 配置が窓に収まる、カードのクリックの座標、受け渡しの流れ（在庫 → 空き枠、枠 → 在庫、上限）、HiRes でない準備が今と同じ、章の情報の集計（兵種・武器・ボス）
5. 目で確かめる: 撮影用の道具（`tools/shot`）で、ch01〜ch03 の準備を撮り、モックと比べる

## 7. 限界・リスク

- 準備画面は、座標を使うコードが多い（クリック判定、行の高さ、タブ）。作り直しで、既存の操作が壊れるおそれがある。**HiRes だけの別の経路にして、HiRes でない準備には触らない**ことで、既存の作品への影響を避ける
- モックは、Pillow で描いた見本で、実際の描画（ビットマップフォント、文字の大きさ）とは、見え方が違う
- 実機の窓で操作していない

### 8.4 設計との違い・未決の点（人の判断を待つ）

1. **戻る操作は置いていない**。承認済みの E-124（DES-IT07 3.5 節「準備の画面からほかの画面へは戻らない」）に従う（今の準備の `cancelPrepare` も、名簿タブでは何もしない）。設計メモ 3 章を、これに合わせて改めた（0.4）
2. **↑↓ と Enter は、今の準備にない**。HiRes の準備にだけ新しく足した（設計への提案。未承認）。決定音・選択音も、これに合わせて HiRes の準備でだけ鳴らす
3. **チェック（`[✓]`）は、モックにない**。設計メモ 3 章の「カードの左端のチェック」に従い、各カードの左端に足した（モックのカードは、これの分だけ右へずれる）。出撃しないカードは暗く描く
4. 設計メモ 3 章の「選んだ状態でもう一度クリックで装備」は作っていない。左クリックは「在庫に戻す」に割り当てたので、装備の切り替えは右クリックだけにした
5. 選んだ品の性能は、モックにも場所がなかったので、手持ちの欄の操作の説明の場所に出す（8.3）。欄の高さの都合で、品を選ぶか指している間は、操作の説明は出ない。品の名前は、枠の下では「小さな爆…」と切れるので、この欄に全文を出す
6. 能力の棒の長さ: HP は最大 30、力〜魔防は 20、移動は 10 で満杯（今の `StatBarLen` の上限 20 に合わせた。HP と移動は設計メモにない実装の判断）。名簿のカードの HP の棒は最大 30
7. 道具の絵は、素材がないので丸（回復薬は赤）。爆弾は、定義の爆発の範囲（`BlastRadius`）で、範囲 0 は橙・小さめ、範囲 1 は灰、範囲 2 以上は暗い赤褐色・大きめにして見分ける（爆弾の ID は使わない）。武器は、既存の種類のタイルを使う（モックの仮のアイコンの代わり）
8. ▲▼ と、武器の相性の早見の → は、ビットマップフォントの字形が画鋲のように見えるので、`vector` の三角・矢印で描く（クリックの範囲は変えない）。早見の見出しは「武器の相性（矢印の向きが有利）」にした
9. 「HiRes の準備」は `Config.HiRes` に従う。ただし窓が 1088×832 なのは `useConfigMetrics` の結果なので、`Config.HiRes` が真で窓が小さい構成は想定しない
10. 既存の TC-DES-NG-10-12（盤面のない場面の配置）の「準備」は、窓の全体に描くようになったので、TC-DES-NG-11-05〜07 へ移した（テスト仕様書 NG04 の該当の行も直した）

### 8.5 目で確かめた結果

撮影用の道具 `tools/shot`（`SHOT_NATIVE=1 xvfb-run -a go run ./tools/shot -game alchemy -hires -scene prepare -chapter ch01|ch02|ch03 [-steps clickpx:x:y,...]`。`tools/shot/README.md` 参照）で、同じ画像を再現できる。ch01〜ch03 の準備と、在庫の行を選んだ状態（爆弾・回復薬）、在庫を送った状態、渡す・戻す・上限（5 枠）の操作後を撮り、モックと見比べた。

- モックと同じ配置で、文字のはみ出し・重なりはない。肖像（512 px）は面積平均で縮めるので、ざらつかない
- 在庫の行を選ぶと、手持ちの欄の下部に、品の名前（全文）と性能が出る（「選んだ品: 小さな爆弾」「道具　爆弾 ダメージ 8　範囲 1　投げる 4」）
- 爆弾の丸は、投げ火（橙・小さめ）、小さな爆弾（灰）、大きな爆弾（暗い赤褐色・大きめ）、回復薬（赤）で見分けられる
- ▲▼ は三角、→ は矢印で描かれ、画鋲のようには見えない。名簿のカードの使用数の箱は、使っている枠が琥珀で塗られる
- 違い: 名前の帯が肖像の上に重なる（モックと同じ）、チェックが足されている、アイコンが仮、ボスの行に「（ボス）」が付く、操作の説明の場所に品の性能が出る
- マウスが指している品の性能は、撮影の道具ではマウスを動かせないので、単体テスト（TC-DES-NG-11-20）で確かめた。窓での実操作は未確認
