## 3. 能力・定義・保存（DES-UNT-01、DES-DAT-04）

### 3.1 型と検証

`defs.Stats`・`tactics.Stats` に `Lck`（幸運）・`Mag`（魔力）・`Res`（魔防）を追加する。`Growth` にも同名を追加する。キーは `base.lck/mag/res`、`bonus.lck/mag/res`、`growth.lck/mag/res`。能力の表示順は HP・力・魔力・技・速さ・幸運・守備・魔防・移動。乱数の順は別に下で固定する。

base と bonus の合計は HP≧1、その他≧0。bonus は負を許す。成長率は各 0〜100、移動は成長しない。能力上限は従来どおり設けない。defload と `tactics.New` がそれぞれ検証する。現行の 5 能力の成長を保ち、`rollGrowth` は HP→Str→Skl→Spd→Def→Lck→Mag→Res の順に 8 個引く。0%・100% でも引き、全不成長でも引き直さない。攻撃の全撃の後、経験でレベルが上がる場合にだけ引く。

### 3.4 古い能力の補完（DES-SAV-05）

`core/save.go` の保存を version=2 にし、v1 と v2 の専用 DTO を分けて読む。v1 は追加能力が存在しない形式と確定できるため、正しい 0 を欠落と誤認しない。v2 は 9 能力を必須とし、負数・欠落・未知キーを拒む。未対応版は従来の `ErrSaveVersion`、内容不正は `ErrInvalidSave`。保存 v2 の書き込みは Issue 1 から行い、後続 Issue の武器追加で再度版を上げないよう、武器列と在庫の欄も先に定義する。v2の各名簿には初期単一武器を1要素の列で保存し、後続Issueまでは先頭だけを使う。在庫の武器分は空でもよい。

## 4. 攻撃の計算（DES-BTL-09、DES-BTL-05〜07 の改訂）

### 4.1 式と端数の順

`clamp(x,a,b)=min(b,max(a,x))`。整数で計算し、非負の割算は切り捨てる。A=攻撃者、D=受け手。選んだ攻撃武器と D の装備武器から相性 t を出す。剣→斧→槍→剣が有利＋1、逆は−1、弓・杖・魔法を含む組合せは 0。雷の剣は種類が剣なので物理と同じ三すくみに入る。

| 値 | 新しい式・手順 |
|---|---|
| 攻撃の速さ AS | `max(0, Spd−max(0,武器.Weight−Str))`。魔法も力で支える（E-81） |
| 有効威力 | 武器の特効対象と D の兵種の印が 1 つ以上一致すれば Might×3、それ以外は Might。複数一致しても 3 倍だけ |
| 攻撃力 | 物理: Str＋有効威力＋t。魔法: Mag＋有効威力＋t |
| 通常ダメージ D0 | `max(0,攻撃力−(物理なら Def、魔法なら Res)−受け手の地形.Def)` |
| 命中 | Skl×2＋武器.Hit＋15t＋鼓舞＋条件を満たす狙撃。ここでは範囲に収めない |
| 回避 | 受け手の AS×2＋受け手の地形.Avoid＋鼓舞。幸運は回避には足さない |
| 命中率 H | 全補正後の命中−回避を最後に clamp(0,100) |
| 必殺回避 | 受け手の Lck |
| 必殺率 C | `clamp(floor(Skl/2)＋武器.Crit＋怒り補正−D.Lck,0,100)`。怒りは各撃直前 HP≦floor(最大HP/2) なら＋50。先に clamp してから怒りを足さない |
| 最終ダメージ | 命中時 D0、必殺なら D0×3、その後大盾なら floor(その値/2)。HP は max(0,HP−最終ダメージ) |
| 追撃 | 攻撃開始時の AS 差≧4。守備側は反撃可能な場合だけ追撃する |

怒りの定義は既存 `SkillDef.Chance` / `Skill.Chance` を必殺加算値として使い、skills.tomlのwrathを `chance=50` に改訂する。旧 `multiplier=3` は一般必殺の共通倍率3へ移し、wrathの専用倍率としては使わない。定義の許容範囲はChance 0〜100、wrathのMultiplierは0とする。

AS の下限 0 は計画書の式への**設計上の補足案**（Q-DES06-01）。重すぎる武器で負の回避が発生するのを防ぐ。特効は威力だけを 3 倍にし、能力・相性・最終ダメージ全体を 3 倍にしない。守備地形は魔法にも有効。0 ダメージでも命中・必殺・大盾を判定する。

### 4.2 判定と再現性

1. 各撃に命中の乱数 r1,r2（0〜99）を必ず引く。`r1＋r2 < 2H` なら命中。平均を整数除算してから比べる実装にはしない。
2. **命中時だけ**必殺の乱数 r3 を 1 個引き、`r3 < C` なら必殺。C=0・100 でも命中時は 1 個引く。外れたら必殺も大盾も引かない。
3. 命中し、受け手が大盾を持つときだけ r4 を 1 個引き、`r4 < Chance`（本体 30）なら大盾。必殺倍率の後で半減する。
4. `EventStrike`（既存の Hit/Crit/Pavise/Amount）→ HP が 0 なら `EventFall`。どちらかが倒れたら残りの撃と乱数を省く。全撃後に経験・必要なら成長→勝敗。出来事の評価は 9 章の境界で行う。

同じ IT06 の版・Setup・seed・Command 列と巻き戻しで同じ結果になる。必殺と追加成長で乱数の消費数が変わるため、IT05 と同 seed でも列の一致は保証しない。`Forecast`・AI の候補計算は PCG に触れない。失敗した Command は 1 個も乱数を引かず装備も変えない。

### 4.3 2 回攻撃の武器と反撃

`Weapon.Strikes` は 1 または 2。攻撃開始時の `strikeOrder` の攻撃機会「A→反撃 D→速い側の追撃」を、それぞれの装備武器の Strikes 個の撃に展開する。勇者の斧は自分からでも反撃でも 2 撃。A が勇者で追撃するなら A,A,D,A,A、D が勇者で追撃するなら A,D,D,D,D。両者勇者で A が追撃なら A,A,D,D,A,A。途中の戦死で必ず打ち切る。追撃は最大 1 機会、各側最大 4 撃。

反撃は最後に攻撃に使った武器のまま、射程内であり杖でないときだけ。反撃のために別の武器を選ばない。AS は両者の戦闘開始時の武器で固定し、怒りだけは各撃直前 HP で再判定する。攻撃中の装備変更・成長による追撃再計算はない。

### 4.4 予測（DES-BTL-07）

`ForecastSide` は Name/HP/Damage/HitRate/Count/Skills を残し、`Crit bool` を `CritRate int` に置き換え、`AttackSpeed int`・`Effective bool` を追加する。Damage は必殺・大盾なしの 1 撃、Count は戦死で途中終了しないと仮定した撃数（0〜4）。必殺率は戦闘開始時 HP で表示する。途中で怒りの条件に入る場合は「HP 半分以下で必殺＋50」の説明を出し、確定ダメージ・確定撃破とは表示しない。反撃不能側は回数 0 と「反撃なし」を出す。

射程・相性・特効・補正スキルは選択中の武器と仮の移動先で計算する。武器を選び直すと更新し、取消しで本当の装備に影響しない。必殺率は命中後の確率であり、命中率との積を表示しない。

## 6. 手持ち・装備・在庫（DES-ITM-02）

### 6.1 状態と Command

既存 `Items []ItemStack` は道具用に残し、`UnitSetup/Unit.Weapons []Weapon` と `Equipped int` を追加する。`Weapon` は本物の状態として重複保存せず、装備武器を返す参照へ移す（呼出箇所をまとめて変更）。tactics へ単一 `Weapon` を渡す旧 Setup は Weapons の 1 本へ正規化する互換口を Issue 1 に置き、両指定を拒む。Weapon に外側への返却用 `ID string` を持たせ、定義検索には使わない。`UnitSetup/Unit.AllowedWeaponTypes []WeaponType` へ兵種の許可種を値として渡し、Newは各所持武器と装備添字を検証する。旧単一武器Setupで許可種を省略した場合だけ、その1本の種へ正規化する。

本数＋道具の Count 合計≦5。杖も 1 本 1 枠、同 ID の武器を複数持つ場合も 1 本ずつ位置と杖の回数を区別する。Items の行数では数えない。戦闘中の受け渡し・拾得・並べ替え・任意装備だけのコマンドは追加しない。

`Command.Weapon *int`（武器列の添字）を追加する。nil は現在装備、Attack・Heal では非 nil で選択できる。Attack は武器の存在→許可種→攻撃可→相手→射程、Heal は選択した杖→残回数→相手→射程→HP の順に既存共通検証の後で確かめる。予測も同じ検証。無効添字は新しい `ErrNoWeapon`、使えない種は `ErrWeaponType`。待機・薬で Weapon を指定した場合は `ErrInvalidAction` とする。

成功した Attack でのみ Equipped を指定武器に変える。外れても「攻撃に使った」に含む。反撃・追撃もその武器。Heal は選択杖の回数だけを減らし装備は変えず、薬と待機でも装備は維持する。錬金術師は魔法の後で回復しても魔法で反撃し、最初から杖を先頭にして出た場合は一度攻撃するまで反撃しない。初めの装備は準備で並べた Weapons[0]。次章も先頭から開始し、最後の攻撃武器は戦闘内だけの状態にする。

`AttackRange` は選択武器の範囲を求める口を追加する。敵の危険範囲は手持ちの全攻撃武器の射程の和集合とし、杖を除く。敵 AI は持ち替えて攻撃できるので、現在装備だけに限定しない。自軍の表示は攻撃武器の赤と選択杖の緑を区別する。手持ち・武器内の特効列・スキル列は Units/Event/BoardView/履歴で深く複製する。

### 6.2 キャンペーン・準備・報酬

`Member.Weapons []string`（順序を保存）を追加し、`Items` は従来の道具列。`defs.ItemCount` に `Weapon string` を追加し、在庫・reward は Item と Weapon のどちらか一方だけを持つ列として扱う。例 `reward=[{weapon="armor_killer",count=1},{item="potion",count=1}]`。参照先が実在し Count≧1、両方・両方空は拒む。道具の `items` では Weapon を許さない。ゲーム初期在庫も同型にできるが新武器の配布は報酬のみとする。

キャラ・敵定義は `weapons=["fire","heal_staff"]` を追加、旧 `weapon` は 1 本へ正規化、併記不可。今の仲間の初めの鉄と薬、錬金術師の基本魔法と杖以外の新武器は章の報酬で在庫へ入れる。報酬の仮配分は ch01 アーマーキラー、ch02 ハンマー、ch03 ホースキラー、ch04 キルソード、ch05 長弓、ch06 雷の剣、ch07 勇者の斧、ch08 ファイアを各1本。敵の武器は敵定義から供給しドロップしない。段階 6 の試遊で配分を確定する。

`TakeItem/StoreItem` は道具のまま、`TakeWeapon(member,id)`・`StoreWeapon(member,index)`・`MoveWeaponFirst(member,index)` を足す。クリア済み→生きた名簿→在庫または所持→兵種の許可→合計枠の順で検証し、成功時だけ一度に移す。装備不可武器を単なる荷物として持たせない。準備の「持たせる」「外す」「先頭へ」は武器と道具を表示する。最後の 1 本を外す操作は `ErrLastWeapon` で拒む案とする（出撃時に無武器になる状態を増やさない、Q-DES06-04）。出撃の際にも 1 本以上を検証する。杖だけの僧侶は可。

`FinishChapter` は出撃者の武器列・残った道具を最終 Battle から戻し、報酬を一度だけ在庫へ足す。杖の回数は名簿に残さず、新しい章の New で全所持杖を満タンにする。離脱と戦死者の扱いは既存どおりで、武器を自動回収する新ルールは足さない。

### 6.3 v1 の所持品移行

v1 には武器所持も武器在庫もない。各既存名簿にその CharacterDef の初期武器を 1 本支給し、旧道具は保存順・各個数順に後ろへ並べる。先頭から合計 5 枠まで手持ちに残し、溢れた道具を同じ ID の在庫へ加える。たとえば旧「薬5個」＋鉄1本は鉄1本・薬4個、在庫に薬1個。武器が複数の定義になった場合も先頭から同じ規則で残し、超過武器を在庫へ戻す。死亡者も移行を一度だけ行い、生死を変えない。

武器在庫は `game.stock` の初期武器分から作る（推奨案では空）。v1 の攻略済み章の新武器報酬は遡及支給しない。重複配布を避け、以後の章の報酬で入手する案（Q-DES06-05）。旧道具在庫に初期薬を重ねて加えない。v2 は保存武器・在庫を正とし、5 枠超過は壊れたデータとして拒む。v1→v2→v2 で所持と在庫の合計数が不変であることを検証する。

## 7. 回復・経験・敵レベル

### 7.1 杖の回復（DES-HEL-01・02 の改訂）

基本回復量を `選択杖.Heal＋使用者.Mag` とし、実回復量は `min(基本回復量,対象の最大HP−HP)`。回復薬・砦には魔力を足さない。回復で命中・必殺・大盾は判定せず、経験は 10、レベルが上がるときだけ成長乱数を引く。杖の射程・自己回復不可・満タン不可・章ごと満タンは維持する。

錬金術師は同じ癒やしの杖でも兵種で回復の合計に上限 8 を置く案とする。`ClassDef.StaffHealCap`（`staff_heal_cap`、0=上限なし）を `UnitSetup/Unit.StaffHealCap` に変換し、基本回復量をまず cap で制限してから対象の不足 HP で制限する。新しい種類の杖を増やさず、攻撃・回復両用の代わりに回復能力を低くする。錬金術師に杖の回数を減らす案は採らず、全杖15回を保つ。これは計画書12章の「回復量が低め」を具体化した**設計への提案**であり承認待ち（Q-DES06-06）。

回復例 H1: リナ魔力0なら10＋0=10、ハンナ魔力3なら13。HP10/24の相手にはそれぞれ10、13回復し20/24、23/24。錬金術師は10＋3=13→上限8→min(8,14)=8で18/24。成長後リナ魔力4なら min(14,14)=14、24/24。

### 7.2 経験（DES-GRW-04、DES-GRW-01〜03 の改訂）

攻撃の流れに加わった、生き残った自軍の 1〜19 レベルだけが経験を得る。敵の反撃を受けて生き残っただけの追加経験は作らないが、現行の「1 撃も行えなくても流れに加わり生き残れば1」は維持する。倒した場合の経験は `clamp(30＋(敵Level−自軍Level)×3,10,50)`、1 回以上命中なら10（0ダメージを含む）、その他1。重複加算せずこの順に1つを選ぶ。反撃・勇者の複数撃でも流れ全体で1回。

| 改訂 ID | 元 → 新 |
|---|---|
| DES-GRW-01 | 撃破30固定 → 上式の10〜50。撃破時点のレベル（成長前）で算出 |
| DES-GRW-02 | 1回≦30、99＋30 → 1回≦50、99＋50=149。1レベルまで、100を引いて余りを持つ、Lv20では経験0は維持 |
| DES-GRW-03 | Exp.Amount が1/10/30 → 1または10〜50（実際の式で出る整数）。Gains に3能力を追加、ExpとLevelUpの写しはともに成長後 |

経験例 G1: Lv17対Lv8は30＋(8−17)×3=3→10。G2: Lv6対Lv10は30＋4×3=42。G3: Lv1対Lv20は87→50。G4: Lv6経験99で42なら141→Lv7経験41。G5: Lv19経験95で10なら105→Lv20経験0。

### 7.3 敵レベルと制作の目安

章が参照するマップを敵配置の原本とする現構成を維持し、`EnemyPlacement.Level int` を追加し、maps.toml の初期敵・ターン増援・出来事増援すべてに `level` を書く。省略は互換読込では1、0と21以上は拒む。本体は全個体に明記する。敵の Level を 0 に限る `validateGrowth` の検証を 1〜20 へ改訂、敵 Exp=0・Growth=全0 を要求する。`gainExp` の Side==Player 条件を残すので敵は一切育たない。自軍 Level=0 を成長しないテスト入力として使う既存の契約は維持する。兵種 base＋個体 bonus が実能力で、Level からの自動補正は行わない（E-86）。

## 8. 騎兵の再移動（DES-BTL-10）

### 8.1 兵種スキル

`ClassDef.Skills []string`、`classes.skills=["canto"]` を追加。skills.toml の `canto` は `effect="canto"`、数値なし。`UnitSetup/Unit.ClassSkills []Skill` へ変換し、既存の `Skill` はキャラ1つとして残す。キャラと兵種の両方を統合して効果を判定し、同じ効果を二重適用しない。兵種の列の重複と不正な効果を検証する。cavalierだけがcanto、他兵種は空。エルザのキャラ枠は現在空だが、そこに既存スキルを指定してもcantoと両立する（E-86 の2枠）。新しいキャラスキルは付与しない。

### 8.2 自軍の操作と Command

再移動対象は Attack/Heal/UseItem のあとで、生きていて勝敗未決、canto があり残移動力>0の場合。Wait は通常の移動で完了。残移動力は `Mov−行動前位置からCommand.ToへのReachable最小費用`、歩数ではない。再移動は行動後位置から同じ地形費・占有規則でその残量まで。経験で Mov は増えない。行動後の盤面で再計算し、敵を倒して空いたマスも使える。

`Act` は攻撃結果を返して `PendingCanto`（ユニット・残量・行動前history参照）を保持する。新 `Action.CantoMove`・`Action.CantoEnd` を末尾に追加し、同じ `Command{Unit,To,Action}` で確定する。CantoEnd の To は現在位置に限る。保留中は当該2操作・巻き戻しだけ受け付け、他ユニットの行動と EndPhase は `ErrCantoPending`。再移動先不正は状態・乱数・保留を変えない。移動して再び行動することはできない。

履歴の before は最初の移動前を一度だけ保存し、移動＋行動＋再移動完了を1手とする。保留中も同じ before に巻き戻せるよう最初の Act 成功で履歴を公開し、続く再移動はその履歴を閉じるだけで新しい1手を作らない。最後の自軍が行動しても、保留が終わるまで自動の敵軍開始を遅らせる。戦死・勝敗決定・残量0なら保留を作らず通常どおり閉じる。`snapshot` に保留と深い武器列を含め、プレビューは移動前を示す。行動後の再移動を取り消す Esc は現在地で完了する操作であり、攻撃結果だけを無料で取り消す操作にはしない。

再移動例 C1: Mov7、森2＋平地1の費用3を使って攻撃したら残4。再移動で森2＋平地1を使う移動は可、合計費用5は不可。再移動しなければ残量は捨てる。

### 8.3 敵の再移動

敵も同じ費用計算・canto効果を使い、攻撃後に生存・勝敗未決なら1回退避する。敵の1手の履歴に含め、中断入力待ちは作らない。退避先の比較は10.3節。敵は杖・道具を使わない現行規則を維持するので、実際の敵の再移動契機は攻撃だけ。

## 9. 出来事の増援・突撃（DES-MAP-07）

### 9.1 定義の形

`EnemyPlacement` に `id`（マップ内で初期敵・全増援を通して一意）と `group`、`MapDef.Events` を追加する。従来データの省略IDは読込時に配置種別＋定義添字で一意に生成できるが、参照される敵には明示IDを必須とする。名前・生存添字を識別子にしない。

```toml
[[maps.events]]
id = "gate_alarm"
trigger = "enemy_attacked"
unit = "gate_guard"
effect = "reinforce"
# 出現候補の予兆はこの増援座標から既存と同じ方法で導く
[[maps.events.enemies]]
id = "reserve_1"
class = "mage"
level = 7
weapons = ["fire"]
ai = "charge"
x = 0
y = 4

[[maps.events]]
id = "advance"
trigger = "player_entered"
area = { min_x = 3, min_y = 4, max_x = 7, max_y = 8 }
effect = "charge_group"
group = "gate_group"
```

各出来事はきっかけ1つ・効果1つ・1回限り。同じきっかけに2効果を付けるには2件書く。trigger は enemy_moved / enemy_defeated / enemy_attacked / player_entered。前3つは unit が必要、areaは禁止。最後は両端を含む盤内矩形が必要、unitは禁止。effect は reinforce / charge_group の2つを推奨（Q-DES06-07）。前者はenemiesが1体以上、後者は実在するgroupとし不適切な欄の併記を拒む。イベントID重複・敵ID重複・参照欠落・逆矩形・盤外・ボス増援・敵杖・不正能力も拒む。循環した「倒されないと出ない敵」の参照は制作検査で報告し、詰みを構文の合格と混同しない。

### 9.2 観測・発火・出来事の順

`enemy_moved` は指定敵の実際の EventMove（通常移動・再移動を含む、同じ位置への待機は除外）。`enemy_defeated` は EventFall。`enemy_attacked` は指定敵を受け手とする EventStrike が試みられたこと（外れ・0ダメージ・反撃も含む）。`player_entered` は自軍の実移動の到着マスが矩形内になること（初期配置・経路の通過だけは含まない）。それぞれを行動中に記録し、攻撃の途中へ効果を割り込ませない。

各通常行動の移動・全撃・戦死・経験・成長・勝敗を済ませたあと観測を消費し、未発火の定義を記述順で評価する。再移動はその Move のあとに同じ評価を行う。1件が成立したら発火済みにしてから効果を適用する。複数の観測で同じ件が成立しても1回。勝敗が決まった場合は追加の効果を実行しない。効果自体は4種のきっかけを新しく発生させないため、その境界で連鎖を再帰評価しない。`EventTrigger` と `EventGroupCharge` を既存 EventKind の末尾に追加し、順は原因の出来事→経験等→Trigger→予約またはGroupChargeとする。

### 9.3 増援予約・予兆・巻き戻し

即出現と予兆不足を避け、reinforce は**次に来る敵軍開始**へ予約する案。自軍番で起きれば当該ターン、敵番で起きれば次ターン。予約後から既存の粗い矩形の予兆を出す。正確な位置・人数・レベル・ターンの一覧を出さない。突然同じ行動の途中に現れて攻撃はしない（Q-DES06-07）。

敵軍開始の順は PhaseStart→既存ターン増援（定義順）→予約出来事増援（出来事定義順・個体順）→砦回復。場所は DES-MAP-03 の距離0〜2・Y・X順、空きがなければその個体は不出現・延期しない。発火済みは戻さない。その番は新しい増援を動かさず、次の敵軍番から参加する。敵番の最中に予約された分も次の開始時に出し、その開始番には動かさない。

charge_group は既存の Hold を Charge にし、10章の思考方式は変えない。処理済み敵を同じ番に再び動かさない。未出現の同groupにも適用できるようgroupの活性状態を保持する。

状態は `fired []bool`、予約列（出現予定ターン・定義参照・消費状態）、groupの活性・集合状態、出現個体の行動可能番。`Battle.New` で初期化、snapshot/restore と PreviewRewind に深く含める。予兆は予約と進行位置から毎回導く。元の戦闘と履歴のプレビューの予兆を混ぜない。章間セーブには入れず、やり直しでは未発火へ戻す。観測の一時列も境界で処理・消去し、保留された再移動の前後で失わない。

## 10. 敵の思考（DES-AI-02、DES-AI-01 の改訂）

### 10.1 従来思考と候補比較

`ai="charge"/"hold"` は動き出す条件として維持し、独立した `approach="direct"/"group"` を追加する（省略direct）。group方式には空でないgroupが必要。同じ一団の方式はそろえる。Holdのgroupは一員に攻撃候補ができたこと、またはcharge_groupで活性化してから集合を始め、それまでは待つ。候補を得ても集合方式なら下の集合制約を先に適用し、単独の攻撃へ直行しない。directのHoldは従来どおり攻撃成立でChargeにする。章のデータで敵ごとに選び、全敵を集合方式にはしない。既存の `Charge`/`Hold` に新しい値を兼用せず、UnitSetup/Unit に `Approach` と `Group` を持たせる。

候補は「到着マス・相手・使用可能な攻撃武器」の組。優先順は従来の (1) 通常ダメージ×撃数≧相手HP、(2) ダメージ×表示命中率×撃数が大、(3) 反撃の同積が小、(4) 自軍添字が小、(5) 到着Y・Xが小、最後に (6) 武器列添字が小。必殺・大盾の期待値と乱数は用いない。最初の方から止めず、全候補を決定的に比較する。従来directは攻撃候補がなければ `closeness` を小さくする既存の寄り方を保つ。集合中に限り下の制約で候補を絞り、弱者を狙う新しい優先度は作らない。

### 10.2 一団でそろってから入る規則案

「割に合わない相手」は、各敵から見て、相手からその敵への予測の通常総ダメージが敵の現在HP以上、または命中率を掛けた相手の総ダメージが敵から相手への総ダメージ以上の自軍とする。比較にはそれぞれその位置で使える武器の最良候補を使う。大盾・必殺・将来の味方の攻撃は数えない。下がる相手の判定に使い、攻撃対象の弱者狙いには使わない（Q-DES06-08）。

割に合わない相手の Reachable と全攻撃武器の射程の和集合を、その敵に対する危険域とする。Holdかどうかに関わらず自軍の次の移動＋攻撃範囲を使う。割に合うかの比較は、相手の各到達位置から敵の現在位置へ合法に攻撃できる候補を列挙して行い、その位置で敵から反撃できない場合の敵側総ダメージは0とする。複数の相手候補は10.1節の比較で最良のものを選ぶ。到達・射程外なら危険な相手として数えない。

集合先は、同一の戦場の自軍へ寄る `closeness` が小さい危険域の直外の通行可マス（危険域と上下左右で接する安全マス）。危険域なしなら従来のChargeとして入る。安全な集合先の割当は生存敵添字順、距離費用→Y→X順で重ならないように行う。境界の比較はcloseness→そこまでの地形費→Y・X、後列の候補も同じ同点順とする。移動では自軍に近づく既存の経路を使い、別経路を回って弱い敵を探す機能を足さない。

集合先の割当と一斉判定は各敵軍番の開始（増援・砦回復の後）に一度行い、その番の間は保持する。途中でgroupが活性化した場合は次の敵軍番から集合処理に参加し、処理済みの敵をやり直さない。活動中で生存・出現済み、かつ同じ到達可能領域のgroup構成員を参加者とし、全員が割り当て集合先に到着済みならその番は全員の突入を許可する。先頭の敵がその番に到着しただけでは後続も含めて突然突入しない。突入状態はgroupに保持し、再集合を繰り返さない。戦死者と未出現増援を待たない。

集合中に安全な集合先へ今番で届かない敵は、安全域のうち割当先までの移動費が最小のマスへ寄る。すでに危険域内にいる敵は、すぐ退避できれば集合先へ下がり、逃げ場がなければ通常の候補比較で攻撃する。安全な集合先を人数分確保できない狭路では、確保できた最前列に隣接する安全域へ後列を割り当てる。安全域自体が足りなければ現位置で待つ。離れた到達不能領域の構成員は別の集合判定とし、未出現の仲間を理由に停止しない。狭路で集合できず停止し続ける配置は制作不備として試遊で直す。時間制限で無条件に突っ込む規則は足さない。

### 10.3 敵騎兵の退避

行動後の盤面で残移動内のマスを列挙し、(1) 自軍の次回移動＋全攻撃武器の攻撃範囲に入る人数が少ない、(2) 最も近い生きた自軍からのマンハッタン距離が大きい、(3) 今の位置からの消費が少ない、(4) Y・Xが小さい、の順。今の位置も候補とし、動かない方がよいなら動かない。反撃のあと戦死した敵は再移動しない。集合中の例外攻撃でも同じ退避規則を使う。退避後のgroup再集合は行わない。

### 10.4 思考時間（NFR-02）

32×32・総40体、手持ち最大5なので候補は概ね「敵数×到達マス×自軍数×武器数」。全行動の未来の組合せ探索はしない。到達範囲・自軍の危険域・closeness は同じ盤面について再利用し、移動・戦死・出現・装備変更後は無効化する。groupの突入判定を敵1体ごとにやり直さない。走査順と同点規則を固定し、キャッシュの有無で結果を変えない。

1秒以内という要求は維持するが、今回の設計作成で達成したとはしない。E-72 に従い、待ちを感じたら外側で敵番の思考時間（再生時間を除く）を測り、盤面・体数・所持武器・環境・時間を記録する。core に時計を入れない。遅い場合は局所的な再計算を見直し、思考や再移動を黙って範囲から外さない。

## 12. 画面と入力

### 12.1 武器選択（DES-UI-26）

通常は移動先→攻撃→武器→相手→予測→決定。武器一覧は最大5行で、名前・物理/魔法・威力・命中・必殺・重さ・射程・特効印を詳細欄へ出す。対象に届く武器がなければ理由を表示する。決定するまでcoreの装備は変えない。右クリック/Escは予測→相手→武器→行動一覧→移動先選択の順に戻り、未確定移動と武器を取り消せる。回復は行動一覧→杖選択→対象→回復予測。錬金術師には攻撃と回復の両方を出す。

準備では道具と武器を同じ5枠として「3/5」のように表示し、武器列の先頭に「初期装備」を付ける。在庫・名簿はスクロールし、9人目・5枠目でも案内やボタンと重ならない。装備不可は選べない理由を出す。

### 12.2 予測と情報

予測に「通常ダメージ×撃数」「命中%」「必殺%」「攻撃の速さ」を両側に出す。特効は文字で強調し、有効威力を詳細に出す。大盾30%・怒り＋50条件・狙撃・鼓舞の説明を保持し、必殺確定の旧表示を廃止する。武器の速さ低下量と反撃不能も分かるようにする。

情報欄は追加3能力と敵レベル、装備と全所持武器、キャラと兵種の両スキルを出す。「能力」「装備・スキル」の2ページ（クリックとTabで切替）に分け、ページ切替は表示のみ。予測を開いている間は予測の表示を優先する。長い名前を省略しても選択行の詳細では全文を読める。

### 12.3 再移動

行動の再生後に `PendingCanto` があれば再移動状態へ入り、残量と到達マスを表示しクリックで CantoMove、現在地クリックまたは「終える」・Escで CantoEnd。まだほかのユニットを操作できないことを案内する。攻撃の決定前の取消しと、結果が出たあとの再移動終了を区別する。巻き戻しは通常と同じ入口から移動前へ戻す。敵の再移動は通常Moveとして再生し、攻撃前後の移動が履歴の同じ1行に含まれる。

### 12.4 操作4点（DES-UI-27）

1. 配置画面は `DeploymentView` の初期敵をホバーして能力を表示し、敵クリックで味方の配置を入れ替えない。未出現増援は見せない。
2. 情報の優先順は「予測等の専用表示→ホバー中の生きたユニット→選択中ユニット→地形」。カーソルが盤外・空きマスへ出たら選択中へ戻る。表示の切替は選択・配置を変えない。
3. 敵の個別範囲は添字の集合で保持する。通常の敵クリックは追加、同じ敵の再クリックは削除。自軍選択やスクロールでも保持し、位置・装備・生死変化後に再計算する。戦死敵は除き、別Battleでは空。巻き戻し成功時も同じ添字集合を復元盤面に照合し、生存者のみ表示する。Qの全敵範囲とは別の設定で、重複マスは和集合にする。
4. 自軍の移動先選択中に敵をクリックした場合は範囲固定より簡易攻撃を優先する。移動可能な攻撃位置と手持ち武器を列挙し、まず武器選択へ進み、その武器で「現位置から攻撃可なら現位置、そうでなければ移動費が最小、同点Y・X」の仮移動先を選ぶ。予測上で移動先を示し、通常の確認で確定する。候補がなければ理由を出し移動先選択を保つ。この操作でも即座に乱数を引かない。

### 12.5 ミニマップ（DES-UI-28）

832×576、盤面は従来の左512×512（16×16マス）を保ち、**情報欄を狭くする**。右情報欄は x=512〜831、y=0〜359 の320×360、右下 x=512〜831、y=360〜511 の320×152をミニマップ専用にする。案内欄y=512〜575は従来どおり。地図本体は x=604〜731、y=376〜503の128×128以内へ等比縮小し、余白に枠と凡例を置く。32×32なら1マス4px、16×16なら8px。長方形は中央に余白を付ける。

地形の色、自軍青・敵赤、現在の表示範囲の白枠、既知の予兆だけを描く。全滅敵・未出現増援の位置を表示しない。通常戦闘・配置・巻き戻しプレビューでは、それぞれ参照している BoardView で常設する。メニューや予測を地図の上に重ねない。下部情報のページ送りはミニマップを動かさない。

地図クリックでカメラ中心をその世界座標へ移し、`Camera` の既存上限で止める案。ドラッグは足さず、余白クリックは無視。移動・攻撃コマンドとして扱わずPCG・履歴・範囲固定を変えない。Playingの自動追尾中はクリック移動を無効とし、再生後は通常の入力へ戻す。下の行の地図でも敵選択と誤認しないよう、入力判定はミニマップ→情報→盤面の順（Q-DES06-10）。
