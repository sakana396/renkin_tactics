## 3. 能力・定義・セーブ（DES-UNT-01、DES-DAT-04）

### 3.1 型と検証

- `defs.Stats`・`tactics.Stats` に `Lck`（幸運）・`Mag`（魔力）・`Res`（魔防）を足す。`Growth`（成長率）にも同じ名前で足す
- TOML のキーは `base.lck/mag/res`（兵種の初期値）、`bonus.lck/mag/res`（キャラ・敵の上乗せ）、`growth.lck/mag/res`（成長率）
- 能力の表示の順は HP・力・魔力・技・速さ・幸運・守備・魔防・移動。乱数を引く順はこれと別に下で決める
- base と bonus の合計は、HP が 1 以上、ほかは 0 以上。bonus は負でもよい
- 成長率はそれぞれ 0〜100。移動は成長しない。能力の上限は今どおり設けない
- defload と `tactics.New` が、それぞれ検証する
- 今の 5 能力の成長は保つ。`rollGrowth` は HP → Str → Skl → Spd → Def → Lck → Mag → Res の順に乱数を 8 つ引く
- 成長率が 0% や 100% でも乱数を引く。どれも上がらなくても引き直さない
- 成長の乱数は、攻撃の回数をすべて終えたあと、経験でレベルが上がるときだけ引く

### 3.4 古いセーブの能力を補う（DES-SAV-05）

セーブの版と読み方:

- `core/save.go` のセーブを version=2 にする。版 1 と版 2 は、それぞれ専用の読み書き用の構造体で読む
- 版 1 は「足した能力がない形式」と決まっているので、正しい 0 を「欠けている」と取り違えない
- 版 2 は 9 つの能力を必須にし、負の数・欠け・知らないキーを拒む
- 知らない版は今の `ErrSaveVersion`、中身の誤りは `ErrInvalidSave` を返す
- 版 2 で書くのは Issue 1 から行う。後の Issue で武器を足すときにもう一度版を上げなくて済むよう、武器の列と在庫の欄も先に決めておく
- 版 2 の名簿には、初めの武器 1 本を 1 要素の列で保存する。後の Issue までは先頭だけを使う。在庫の武器の欄は空でもよい

版 1 の能力を補う決まり:

- 版 1 の足した能力は `加入のときの base ＋ bonus ＋ floor(max(0, 保存したレベル − 定義の加入レベル) × そのキャラのその能力の成長率 / 100)` で補う
- 前からの HP・力・技・速さ・守備・移動、経験、生死は書き換えない
- 成長の乱数を再現したふりはしない。足した能力だけ期待値の切り捨てを使い、乱数は引かない
- 例: リナ Lv9 なら魔力は `0 ＋ floor(8 × 50 / 100) = 4`
- ロストした仲間も名簿に残し、生死を保つ
- 読み込み用の一時の `Campaign` の上で、検証・移し替え・加入の追いつきをすべて済ませ、成功したときだけ返す
- 読み込むだけでは元のファイルを上書きしない
- 版 2 を読み直したときに、補うことや武器を配ることを繰り返さない

章の間のセーブ:

- 章の間でセーブする決まりは変えない。戦闘の途中の乱数の状態・出来事が起きたかの記録・装備・待っている再移動は JSON に保存しない
- セーブから出撃すると、新しい `Battle` を作る
- クリア済みのセーブはクリア済みのまま読む。新しい章を開いたり、自動で再開したりしない

## 4. 攻撃の計算（DES-BTL-09、DES-BTL-05〜07 の改訂）

### 4.1 式と端数の順

式の中の記号:

| 記号 | 意味 |
|---|---|
| A | 攻撃する側 |
| D | 攻撃を受ける側 |
| t | 武器の相性（有利 ＋1、不利 −1、それ以外 0） |
| Str・Mag・Skl・Spd・Lck・Def・Res | 力・魔力・技・速さ・幸運・守備・魔防（`Stats` の欄） |
| Might・Hit・Crit・Weight | 武器の威力・命中・必殺・重さ（`Weapon` の欄） |
| clamp(x, a, b) | x を a 以上 b 以下に収めた値。min(b, max(a, x)) と同じ |
| floor | 切り捨て |

- 整数で計算し、0 以上の数の割り算は切り捨てる
- 相性 t は、A が選んだ攻撃の武器と、D の装備している武器から出す
- 剣 → 斧 → 槍 → 剣 の向きが有利で ＋1、逆向きは −1。弓・杖・魔法を含む組み合わせは 0
- 雷の剣は種類が剣なので、物理の武器と同じ三すくみに入る

| 値 | 新しい式・手順 |
|---|---|
| 攻撃の速さ | `max(0, Spd − max(0, Weight − Str))`。魔法の武器も力で重さを支える（E-81） |
| 効く威力 | 武器の特効の対象と、D の兵種の分類が 1 つ以上一致すれば Might × 3。それ以外は Might。いくつ一致しても 3 倍だけ |
| 攻撃力 | 物理: Str ＋ 効く威力 ＋ t。魔法: Mag ＋ 効く威力 ＋ t |
| 通常ダメージ | `max(0, 攻撃力 − (物理なら Def、魔法なら Res) − D のいる地形の守備)` |
| 命中 | Skl × 2 ＋ 武器の Hit ＋ 15t ＋ 鼓舞 ＋ 条件を満たした狙撃。ここではまだ範囲に収めない |
| 回避 | D の攻撃の速さ × 2 ＋ D のいる地形の回避 ＋ 鼓舞。幸運は回避に足さない |
| 命中率 | 補正をすべて足した命中 − 回避 を、最後に 0〜100 に収める |
| 必殺回避 | D の Lck |
| 必殺率 | `clamp(floor(Skl / 2) ＋ 武器の Crit ＋ 怒りの補正 − D の Lck, 0, 100)` |
| 怒りの補正 | 1 回の攻撃の直前の HP ≦ floor(最大 HP / 2) なら ＋50。先に 0〜100 に収めてから怒りを足すことはしない |
| 最終のダメージ | 当たれば通常ダメージ。必殺なら通常ダメージ × 3。そのあと大盾なら floor(その値 / 2)。HP は max(0, HP − 最終のダメージ) |
| 追撃 | 攻撃を始めたときの攻撃の速さの差が 4 以上。守る側は反撃できるときだけ追撃する |

怒りと必殺の倍率:

- 怒りは、今の `SkillDef.Chance` / `Skill.Chance` を「必殺率に足す値」として使う。skills.toml の wrath を `chance = 50` に改訂する
- 今の `multiplier = 3` は、怒り専用の倍率としては使わない
- 一般の必殺の倍率 3 は、tactics の定数にする（定義データには置かない）
- 定義で許す範囲は、`chance` が 0〜100、wrath の `multiplier` は 0。DES-DAT-03 の「怒りは `multiplier` 1 以上」の検証をこれに改訂する（1.2 節）

補足:

- 攻撃の速さの下限 0 は、計画書の式に足す**設計の補足**（Q-DES06-01。E-89 で決定）。重すぎる武器で回避が負になるのを防ぐ
- 特効は威力だけを 3 倍にする。能力・相性・最終のダメージ全体は 3 倍にしない
- 地形の守備は魔法の攻撃にも効く
- 通常ダメージが 0 でも、命中・必殺・大盾を判定する

### 4.2 判定と再現性

1 回の攻撃の判定は次の順で行う。

1. 命中の乱数 r1・r2（それぞれ 0〜99）を必ず引く。`r1 ＋ r2 < 2 × 命中率` なら当たり。平均を整数の割り算で出してから比べる実装にはしない
2. **当たったときだけ**、必殺の乱数 r3 を 1 つ引き、`r3 < 必殺率` なら必殺。必殺率が 0 や 100 でも、当たれば 1 つ引く。外れたら、必殺の乱数も大盾の乱数も引かない
3. 当たって、受ける側が大盾を持つときだけ、乱数 r4 を 1 つ引く。`r4 < Chance`（本体の値は 30）なら大盾。必殺の倍率を掛けたあとで半分にする
4. 出来事 `EventStrike`（今の Hit・Crit・Pavise・Amount）を出し、HP が 0 になったら `EventFall` を出す
5. どちらかが倒れたら、残りの攻撃とその乱数を省く
6. 攻撃をすべて終えたら、経験 → 必要なら成長 → 勝敗の順に処理する。出来事のきっかけは 9 章の区切りで評価する

再現性:

- 反復 6 の同じ版で、同じ `Setup`・シード・操作の列・巻き戻しなら、同じ結果になる
- 必殺と成長の乱数が増えて乱数を引く数が変わるので、反復 5 と同じシードでも、乱数の列が一致するとは保証しない
- `Forecast`（予測）と敵の思考の候補の計算は、乱数の状態に触れない
- 失敗した操作は、乱数を 1 つも引かず、装備も変えない

### 4.3 2 回攻撃の武器と反撃

- `Weapon.Strikes`（1 つの機会に攻撃する回数）は 1 か 2
- 攻撃を始めたときの `strikeOrder` が決める攻撃の機会「A の攻撃 → D の反撃 → 速い側の追撃」のうち、A（自分から攻撃する側）の機会だけを、A が装備している武器の `Strikes` の回数に展開する
- D（反撃する側）の反撃と追撃は、武器の `Strikes` によらず、各機会 1 回（E-89。Q-DES06-02）
- 勇者の斧は、自分から攻撃するときだけ 2 回攻撃する。反撃では 1 回。攻める武器であり、受けには向かない
- 例: A が勇者の斧で追撃するなら A, A, D, A, A。D が勇者の斧で追撃するなら A, D, D。両方が勇者の斧で A が追撃するなら A, A, D, A, A
- 途中で倒れたら、必ずそこで打ち切る
- 追撃は最大 1 機会。攻撃は、A が最大 4 回、D が最大 2 回

反撃:

- 反撃は、最後に攻撃に使った武器のまま行う。射程の中にいて、その武器が杖でないときだけ反撃する
- 反撃のために別の武器を選ぶことはしない
- 攻撃の速さは、両者が戦闘を始めたときの武器で決め、途中で変えない。怒りだけは、1 回の攻撃の直前の HP で毎回判定し直す
- 攻撃の途中で装備を替えることや、成長したあとに追撃を計算し直すことはない

### 4.4 予測（DES-BTL-07）

`ForecastSide`（予測の片側）の欄:

- Name・HP・Damage・HitRate・Count・Skills は残す
- `Crit bool` を `CritRate int`（必殺率）に置き換える
- `AttackSpeed int`（攻撃の速さ）と `Effective bool`（特効が効くか）を足す
- Damage は、必殺と大盾を含めない 1 回のダメージ
- Count は、途中で倒れないと仮定した攻撃の回数（攻撃する側は 0〜4、反撃する側は 0〜2）

表示の決まり:

- 必殺率は、戦闘を始めたときの HP で出す
- 途中で怒りの条件に入りうるときは「HP 半分以下で必殺 ＋50」の説明を出す。確定のダメージや確定の撃破とは表示しない
- 反撃できない側は、回数 0 と「反撃なし」を出す
- 射程・相性・特効・補正のスキルは、選んでいる武器と、仮の移動先で計算する
- 武器を選び直すと予測を更新する。取り消しても本当の装備は変わらない
- 必殺率は「当たったうえでの確率」であり、命中率と掛けた値は表示しない

## 5. 武器と兵種の定義（DES-ITM-02、DES-DAT-04）

### 5.1 キーと数値の案

型:

- `WeaponDef`・`tactics.Weapon` に `Crit int`（必殺）・`Weight int`（重さ）・`Strikes int`（1 つの機会の攻撃の回数）・`DamageType`（物理か魔法か）・`EffectiveTags []string`（特効の対象の分類）を足す
- defs の `DamageType` は文字列、tactics では `Physical`・`Magical` の列挙の値にする
- 武器の種類 `WeaponType` は、今の `Staff` の後ろに `Magic` を足す。defs にも `WeaponMagic` を足す

TOML:

- キーは `crit`・`weight`・`strikes`・`damage_type = "physical"`（物理）/ `"magic"`（魔法）・`effective_tags = ["armor"]`（特効の対象）
- 攻撃の武器の `heal`・`uses` は今どおり 0。杖だけが回数を持つ
- 省略したときは `crit` 0、`weight` 0、`strikes` 1、`damage_type` は物理、特効の対象なし。杖の物理・魔法の区分は使わない
- 本体のデータでは、すべて明記する

検証:

- 杖は回復 10、回数 15 を保つ
- 武器の命中は今どおり 0 以上。必殺は 0〜100、重さと威力は 0 以上、攻撃の回数は 1 か 2
- 射程は 1 ≦ 最小 ≦ 最大
- 杖には特効・必殺・2 回攻撃を付けられない。敵は杖を持てない（今のまま）
- 物理／魔法の区分と武器の種類は別のもの。ただし種類 `magic` は魔法の攻撃だけ、`staff` は `heal`・`uses` が必須
- ない特効の対象、重なった特効の対象、知らない区分は拒む
- tactics にも同じ値の検証を置く

### 5.2 兵種が持てる複数の武器の種類と、兵種の分類

武器の種類:

- `ClassDef.WeaponType string` を `WeaponTypes []string` に変える。TOML は `weapon_types = ["magic", "staff"]`
- 読み込みでは、移し替えのために古い `weapon_type` も 1 要素の列に直す。両方を書いたら拒む
- 空・知らない種類・重なりは拒む。手持ちの武器がすべて、兵種が持てる種類に入っていることを確かめる
- 既存の兵種は元の 1 種類だけ。alchemist は magic と staff、mage は magic
- 雷の剣は sword なので、ロード・剣士が持てる

兵種の分類（特効の対象）:

- `ClassDef.Tags []string`、キーは `tags`。armor に `["armor"]`、cavalier に `["mounted"]`、ほかは空
- 特効の対象として書けるのは、この 2 語だけ
- `UnitSetup`・`Unit` に、定義から変えた `Tags []string` を持たせる
- tactics は分類が一致するかだけを調べ、兵種の定義は知らない

- 魔道士（力 1）はファイア（重さ 2）で速さ 5 → 4 と 1 遅くなる。敵の兵種なので、敵の個体ごとに bonus で調べる
- 敵は、その base ＋ bonus を個体ごとに点検する

## 6. 手持ち・装備・在庫（DES-ITM-02）

### 6.1 状態と操作

手持ちの型:

- 今の `Items []ItemStack` は道具のために残す。`UnitSetup`・`Unit` に `Weapons []Weapon`（武器の列）と `Equipped int`（装備している武器の添字）を足す
- 今の `Weapon` の欄は、本物の状態として二重に持たない。装備している武器を返す関数に移す（呼び出すところをまとめて直す）
- tactics に武器 1 本の `Weapon` を渡す古い `Setup` は、`Weapons` の 1 本に直す互換の入口を Issue 1 に置く。両方を指定したら拒む
- `Weapon` に、外へ返すための `ID string` を持たせる。定義を探すのには使わない
- `UnitSetup`・`Unit` の `AllowedWeaponTypes []WeaponType` に、兵種が持てる種類を値として渡す。`New` は、持っている武器と装備の添字をそれぞれ確かめる
- 武器 1 本の古い `Setup` で持てる種類を省いたときだけ、その 1 本の種類を持てる種類にする

5 枠の数え方:

- 武器の本数 ＋ 道具の `Count`（個数）の合計 ≦ 5
- 杖も 1 本で 1 枠。同じ ID の武器を複数持つときも、1 本ずつ位置と杖の回数を分けて持つ
- `Items` の行の数では数えない
- 戦闘の中で渡す・拾う・並べ替える・装備だけを替える、という操作は足さない

操作 `Command`:

- `Command.Weapon *int`（武器の列の添字）を足す。nil なら今の装備。攻撃（`Attack`）と回復（`Heal`）では nil でない値で武器を選べる
- 攻撃は、今の共通の検証のあとで、武器がある → 持てる種類 → 攻撃に使える → 相手 → 射程 の順に確かめる
- 回復は、今の共通の検証のあとで、選んだ杖 → 残りの回数 → 相手 → 射程 → HP の順に確かめる
- 予測も同じ検証をする
- 添字が範囲の外なら新しい `ErrNoWeapon`、持てない種類なら `ErrWeaponType` を返す
- 待機・回復薬で `Weapon` を指定したら `ErrInvalidAction` を返す

装備:

- 成功した攻撃でだけ、装備を指定した武器に変える。外れても「攻撃に使った」に入る
- 反撃・追撃も、その武器で行う
- 回復は、選んだ杖の回数を減らすだけで、装備は変えない。回復薬と待機でも装備は変えない
- 錬金術師は、魔法で攻撃したあとに回復しても、魔法で反撃する
- 錬金術師が杖を先頭にして出撃したときは、一度攻撃するまで反撃しない
- 初めの装備は、準備で並べた `Weapons[0]`（先頭）。次の章も先頭から始める。最後に攻撃に使った武器は、その戦闘の中だけの状態にする

範囲と写し:

- `AttackRange` に、選んだ武器の範囲を求める入口を足す
- 敵の危険な範囲は、手持ちのすべての攻撃の武器の射程を合わせた範囲とし、杖は除く。敵の思考は持ち替えて攻撃できるので、今の装備だけに限らない
- 自軍の表示は、攻撃の武器の赤と、選んだ杖の緑を分ける
- 手持ち・武器の中の特効の対象の列・スキルの列は、`Units`・`Event`・`BoardView`・履歴で深く複製する

### 6.2 キャンペーン・準備・報酬

名簿と在庫:

- `Member.Weapons []string`（順を保つ）を足す。`Items` は今どおり道具の列

キャラ・敵の定義:

### 6.3 版 1 の持ち物の移し替え

- 版 1 には、武器の所持も武器の在庫もない
- 名簿のそれぞれに、その `CharacterDef` の初めの武器を 1 本渡し、古い道具をセーブの順・個数の順に後ろへ並べる
- 先頭から合計 5 枠までを手持ちに残し、あふれた道具は同じ ID の在庫に足す
- 例: 古い「回復薬 5 個」と鉄の武器 1 本なら、手持ちは鉄の武器 1 本・回復薬 4 個、在庫に回復薬 1 個
- 定義で初めの武器が複数になったときも、先頭から同じ決まりで残し、あふれた武器は在庫へ戻す
- 戦死した仲間も一度だけ移し替え、生死は変えない
- 武器の在庫は `game.stock` の初めの武器の分から作る（本体では空）
- 版 1 で攻略済みの章の新しい武器の報酬は、さかのぼって配らない。重ねて配るのを避け、以後の章の報酬で手に入れる（Q-DES06-05。E-89 で決定）
- 古い道具の在庫に、初めの回復薬を重ねて足さない
- 版 2 は、保存した武器と在庫を正とする。5 枠を超えていたら、版 1 と同じ決まりで先頭から 5 枠までを手持ちに残し、あふれた道具を同じ ID の在庫に足す（#120 の版 2 には、武器 1 本 ＋ 道具 5 個のセーブがありうる）。壊れたデータとして拒むのは、武器だけで 6 本以上か、道具だけで 6 個以上のとき（開発者の承認（2026-10-31、REV-072））
- 版 1 → 版 2 → 版 2 と読み書きしても、手持ちと在庫の合計の数が変わらないことを確かめる

## 7. 回復・経験・敵のレベル

### 7.1 杖の回復（DES-HEL-01・02 の改訂）

- 基本の回復量は `選んだ杖の Heal ＋ 使う人の Mag`
- 実際の回復量は `min(基本の回復量, 相手の最大 HP − HP)`
- 回復薬と砦には魔力を足さない
- 回復では命中・必殺・大盾を判定しない。経験は 10。レベルが上がるときだけ成長の乱数を引く
- 杖の射程、自分は回復できない、満タンには使えない、章ごとに満タン、は保つ

錬金術師の回復の上限（Q-DES06-06。E-89 で決定）:

- 錬金術師は、同じ癒やしの杖でも、兵種で回復の合計に上限 8 を置く
- `ClassDef.StaffHealCap`（キー `staff_heal_cap`、0 なら上限なし）を `UnitSetup`・`Unit` の `StaffHealCap` に移す
- 基本の回復量を、まず上限で抑え、そのあと相手の足りない HP で抑える
- 新しい種類の杖は足さない。攻撃と回復の両方ができる代わりに、回復の力を低くする
- 錬金術師の杖の回数を減らす案は採らず、杖はすべて 15 回を保つ
- これは計画書 12 章の「回復量が低め」を具体にしたもの

回復の例 H1:

- リナ（魔力 0）なら 10 ＋ 0 = 10、ハンナ（魔力 3）なら 13。HP 10/24 の相手には、それぞれ 10・13 回復して 20/24・23/24
- ノエル（錬金術師）は 10 ＋ 3 = 13 → 上限 8 → min(8, 14) = 8 で 18/24
- 育ったリナ（魔力 4）なら min(14, 14) = 14 で 24/24

### 7.2 経験（DES-GRW-04、DES-GRW-01〜03 の改訂）

- 攻撃の流れに加わって生き残った、レベル 1〜19 の自軍だけが経験を得る
- 敵の反撃を受けて生き残っただけの追加の経験は作らない。ただし今の「1 回も攻撃できなくても、流れに加わって生き残れば 1」は保つ
- 倒したときの経験は `clamp(30 ＋ (敵の Level − 自軍の Level) × 3, 10, 50)`
- 倒さずに 1 回以上当てたら 10（0 ダメージも含む）、それ以外は 1
- 重ねて足さず、この順に 1 つを選ぶ。反撃や勇者の斧の複数の攻撃があっても、流れ全体で 1 回

| 改訂する ID | 元 → 新 |
|---|---|
| DES-GRW-01 | 撃破 30 の固定 → 上の式で 10〜50。倒したときのレベル（成長の前）で計算する |
| DES-GRW-02 | 1 回の経験は 30 以下、最大 99 ＋ 30 → 1 回の経験は 50 以下、最大 99 ＋ 50 = 149。上がるのは 1 レベルまで、100 を引いて余りを持つ、Lv20 では経験 0、は保つ |
| DES-GRW-03 | `Exp.Amount` が 1・10・30 → 1、または 10〜50（式で出る整数）。`Gains`（上がった能力）に 3 つの能力を足す。`Exp` と `LevelUp` の写しは、どちらも成長のあと |

経験の例:

- G1: Lv17 が Lv8 を倒すと 30 ＋ (8 − 17) × 3 = 3 → 下限の 10
- G2: Lv6 が Lv10 を倒すと 30 ＋ 4 × 3 = 42
- G3: Lv1 が Lv20 を倒すと 87 → 上限の 50
- G4: Lv6・経験 99 で 42 を得ると 141 → Lv7・経験 41
- G5: Lv19・経験 95 で 10 を得ると 105 → Lv20・経験 0

### 7.3 敵のレベルと制作の目安

定義と検証:

- 章が参照するマップを、敵の配置の原本にする今の形を保つ
- `EnemyPlacement.Level int` を足す。maps.toml の初めの敵・ターンの増援・出来事の増援のすべてに `level` を書く
- defload の互換の読み込みでは、省略を 1 として読む。0 と 21 以上は拒む
- 本体のデータは、全員のレベルを明記する。これは定義データの試験（本体の maps.toml の全員に `level` が書いてあること）で確かめる
- 敵の Level を 0 に限る今の `validateGrowth` の検証を、1〜20 に改訂する。敵は Exp = 0・Growth はすべて 0 を求める
- `gainExp` の「自軍だけ（Side == Player）」の条件は残すので、敵は育たない
- 「自軍の Level 0 は成長しない」をテストの入力に使う今の約束は保つ
- 兵種の base ＋ 個体の bonus が実際の能力であり、Level から能力を自動で補正しない（E-86）

Issue 4 の範囲（tactics と試験の補助関数）:

- `tactics.New` は、敵の Level 1〜20 だけを受け付け、0 を拒む。撃破の経験の式に 0 を入れない（0 を許すと、Lv1 の自軍が倒しても 30 − 3 = 27 になり、レベルを書き忘れた敵が黙って弱く扱われる）

- 撃破で 30 を期待している既存のテストは、自軍と敵の Level を書いて期待値を直す（自軍 Lv1 対 敵 Lv1 なら 30 のまま）
- 敵に Level 0 を書いている既存のテスト（`snapshot_test.go`）と、「敵は Level 0」を確かめている検査（`growth_test.go`）は、Level 1 以上の検査に直す

制作の目安:

- 下の表は、今の初めの敵と増援すべての bonus の範囲から付け始める目安
- 参考の能力は `兵種の base ＋ (Lv − 1) × 3.2 節の参考の成長率 / 100`。制作のときは能力ごとに比べ、物理の 5 能力の偏りと装備も確かめる

| ch06 | 4〜11 | 2〜4 | 6〜9 | 11 | ロルフの HP 33・守備 13 と、魔法の相手 |

## 8. 騎兵の再移動（DES-BTL-10）

### 8.1 兵種のスキル

- `ClassDef.Skills []string`（兵種のスキル）を足す。TOML は `classes.skills = ["canto"]`（`canto` は再移動のスキルの ID）
- skills.toml の `canto` は `effect = "canto"` で、数値はない
- 兵種のスキルは `UnitSetup`・`Unit` の `ClassSkills []Skill` に変える。今の `Skill` はキャラの 1 つとして残す
- 効果は、キャラと兵種の両方のスキルを合わせて判定する。同じ効果を二重にかけない
- 兵種のスキルの列の重なりと、正しくない効果を検証する
- 再移動を持つのは cavalier だけ。ほかの兵種は空
- エルザのキャラのスキルは今は空。そこに既存のスキルを書いても、再移動と両立する（E-86 の「2 つ持てる」）
- 新しいキャラのスキルは付けない

### 8.2 自軍の操作と `Command`

再移動できるとき:

- 攻撃（`Attack`）・回復（`Heal`）・道具（`UseItem`）のあと
- 生きていて、勝敗が決まっておらず、再移動のスキルを持ち、残りの移動力が 0 より大きいとき
- 待機（`Wait`）は、今どおりの移動で終わる

残りの移動力:

- `移動力 − 行動の前の位置から Command.To までの最小の費用`。最小の費用は、到達できるマスの計算（`Reachable`）で求める。歩数ではない
- 再移動は、行動のあとの位置から、同じ地形の費用と、同じ「ほかのユニットがいるマス」の決まりで、その残りまで動ける
- 経験で移動力は増えない
- 行動のあとの盤面で計算し直すので、敵を倒して空いたマスも使える

操作:

- `Act` は攻撃の結果を返し、`PendingCanto`（待っている再移動。ユニット・残り・行動の前の履歴への参照）を持つ
- 新しい `Action.CantoMove`（再移動する）・`Action.CantoEnd`（再移動せずに終える）を末尾に足し、同じ `Command{Unit, To, Action}` で決める
- `CantoEnd` の `To` は今の位置に限る
- 待っている間は、この 2 つの操作と巻き戻しだけを受け付ける。ほかのユニットの行動と `EndPhase` は `ErrCantoPending` を返す
- 再移動先が正しくなければ、状態・乱数・待っている再移動を変えない
- 再移動したあと、もう一度行動することはできない

巻き戻しの 1 手:

- 履歴の「前の状態」は、最初の移動の前を一度だけ保存し、移動 ＋ 行動 ＋ 再移動の終わりまでを 1 手とする
- 待っている間も同じ「前の状態」に巻き戻せるよう、最初の `Act` が成功したときに履歴を公開する。続く再移動はその履歴を閉じるだけで、新しい 1 手は作らない
- 最後の自軍が行動しても、再移動が終わるまで自動で敵軍の番を始めない
- 戦死・勝敗が決まった・残りが 0 のときは、待つ状態を作らず、今どおり閉じる
- `snapshot` に、待っている再移動と、深く写した武器の列を含める。巻き戻しの下見は移動の前を示す
- 行動のあとの Esc は「今の位置で再移動を終える」操作であり、攻撃の結果だけをただで取り消す操作にはしない

再移動の例 C1:

- 移動力 7 で、森 2 ＋ 平地 1 の費用 3 を使って攻撃したら、残りは 4
- 再移動で森 2 ＋ 平地 1 を使う移動はできる。合計の費用 5 の移動はできない
- 再移動しなければ、残りは捨てる

### 8.3 敵の再移動

- 敵も同じ費用の計算と再移動の効果を使う。攻撃のあと、生きていて勝敗が決まっていなければ 1 回下がる
- 敵の 1 手の履歴に含め、入力を待つ状態は作らない
- 下がる先の比べ方は 10.3 節
- 敵は杖と道具を使わない（今の決まり）ので、敵が再移動するのは攻撃のあとだけ

## 9. 出来事の増援・突撃（DES-MAP-07）

### 9.1 定義の形

- `EnemyPlacement` に `id`（マップの中で、初めの敵・すべての増援を通して重ならない）と `group`（一団の名前）を足す。`MapDef.Events`（出来事の列）を足す
- 今のデータで ID を省いた敵は、読み込みのときに「配置の種類 ＋ 定義の添字」で重ならない ID を作れる。ただし、出来事から参照される敵には ID を書くことを必須にする
- 名前や、生きている敵の添字を識別子にしない

```toml
[[maps.events]]
id = "gate_alarm"
trigger = "enemy_attacked"
unit = "gate_guard"
effect = "reinforce"
# 出てくる場所の予兆は、この増援の座標から今と同じ方法で出す
[[maps.events.enemies]]
id = "reserve_1"
class = "mage"
level = 7
weapons = ["fire"]
ai = "charge"
x = 0
y = 4

[[maps.events]]
id = "advance"
trigger = "player_entered"
area = { min_x = 3, min_y = 4, max_x = 7, max_y = 8 }
effect = "charge_group"
group = "gate_group"
```

出来事の決まり:

- 1 つの出来事は、きっかけ 1 つ・効果 1 つで、1 回だけ起こる。同じきっかけに 2 つの効果を付けるなら、2 件書く
- きっかけ `trigger` は 4 つ。`enemy_moved`（指定の敵が動いた）・`enemy_defeated`（指定の敵が倒れた）・`enemy_attacked`（指定の敵が攻撃された）・`player_entered`（自軍が指定の範囲に入った）
- 前の 3 つは `unit`（指定の敵の ID）が必要で、`area` は書けない
- `player_entered` は `area`（両端を含む、盤の中の長方形）が必要で、`unit` は書けない
- 効果 `effect` は `reinforce`（増援を出す）・`charge_group`（指定の一団を突撃にする）の 2 つとする（Q-DES06-07。E-92 で決定）
- `reinforce` は `enemies` が 1 体以上、`charge_group` は実在する `group` が必要。合わない欄を一緒に書いたら拒む

拒むもの:

- 出来事の ID の重なり、敵の ID の重なり、参照先がない
- 長方形の向きが逆、盤の外
- ボスの増援、杖を持つ敵、正しくない能力

制作の検査:

- 「倒さないと出てこない敵」を循環して参照しているものは、制作の検査で報告する。詰むことを、構文の検査に合格したことと取り違えない

### 9.2 観測・発火・出来事の順

きっかけの観測:

- `enemy_moved`: 指定の敵の実際の `EventMove`（ふつうの移動と再移動を含む。同じ位置での待機は含まない）
- `enemy_defeated`: 指定の敵の `EventFall`
- `enemy_attacked`: 指定の敵を受ける側とする `EventStrike` が試みられたこと。外れ・0 ダメージを含む。指定の敵が自分から攻撃して反撃されたときも含める（Q-DES06-07。E-92 で決定）
- `player_entered`: 自軍が実際に移動して、着いたマスが長方形の中にあること。初めの配置と、経路で通り過ぎただけのときは含まない
- 観測は行動の途中で記録しておき、攻撃の途中に効果を割り込ませない

評価と発火:

- ふつうの行動の、移動・すべての攻撃・戦死・経験・成長・勝敗を済ませたあとで、観測を使い、まだ起きていない出来事を書いた順に評価する
- 再移動は、その移動のあとで同じ評価をする
- 1 件が成り立ったら、まず「起きた」にしてから効果をかける
- 複数の観測で同じ件が成り立っても 1 回だけ
- 勝敗が決まったら、それ以上の効果はかけない
- 効果そのものは 4 つのきっかけを新しく起こさないので、その区切りで連鎖を繰り返し評価しない

出来事の種類と順:

- 出来事 `EventTrigger`（きっかけが成り立った）と `EventGroupCharge`（一団が突撃に変わった）を、今の `EventKind` の末尾に足す
- 順は、原因の出来事 → 経験など → `EventTrigger` → 増援の予約または `EventGroupCharge`

### 9.3 増援の予約・予兆・巻き戻し

予約と予兆:

- すぐに出てくることと、予兆が足りないことを避けるため、`reinforce` は**次に来る敵軍の番の始め**に予約する（Q-DES06-07。E-92 で決定）
- 自軍の番で起きたら、そのターンの敵軍の番。敵軍の番で起きたら、次のターンの敵軍の番
- 予約したときから、今と同じ大まかな長方形の予兆を出す。正確な位置・人数・レベル・ターンの一覧は出さない
- 同じ行動の途中に突然現れて攻撃することはない（Q-DES06-07）

敵軍の番の始めの順:

- 番の始まり（`PhaseStart`）→ 今のターンの増援（定義の順）→ 予約した出来事の増援（出来事の定義の順・個体の順）→ 砦の回復
- 出る場所は DES-MAP-03 の距離 0〜2、Y・X の順。空きがなければ、その個体は出ず、先送りもしない
- 一度に生きている敵は 39 体まで（E-91）。tactics の定数 `maxLiveEnemies = 39` にする
- 出現の順（ターンの増援 → 予約した出来事の増援、それぞれ定義の順・個体の順）に 1 体ずつ判定し、出すと生きている敵が 39 を超える個体は出さない。先送りもしない（空きがないときと同じ扱い。Q-DES06-13。E-92 で決定）
- 上限で出なかった個体は `EventReinforce` に含めない。乱数は引かない。その出来事は「起きた」のまま戻さない
- 予兆は今どおり定義と予約から出す。出現のときに上限で出ないことがありうる（予兆は「来るかもしれない」範囲であり、約束ではない）
- `tactics.New` は、初めの敵が 39 体を超える `Setup` を拒む
- 起きた出来事は「起きていない」に戻さない
- その番に出た新しい増援は動かさず、次の敵軍の番から加わる
- 敵軍の番の途中で予約された分も、次の番の始めに出し、その番には動かさない

一団の突撃:

- `charge_group` は、今の `Hold`（待つ）を `Charge`（突っ込む）にする。10 章の思考の方式は変えない
- その番に処理し終えた敵を、同じ番にもう一度動かさない
- まだ出ていない同じ一団の敵にもかけられるよう、一団が動き出したかの状態を持つ

状態と写し:

- 状態は、`fired []bool`（出来事ごとに起きたか）、予約の列（出る予定のターン・定義への参照・使ったか）、一団の動き出し・集まりの状態、出てきた個体が行動できる番
- `Battle.New` で初期化し、`snapshot`・`restore` と巻き戻しの下見（`PreviewRewind`）に深く含める
- 予兆は、予約と進み具合から毎回求める。もとの戦闘と、履歴の下見の予兆を混ぜない
- 章の間のセーブには入れない。やり直したら、すべて「起きていない」に戻す
- 観測の一時的な列も区切りで処理して消す。待っている再移動の前後で失わない

## 10. 敵の思考（DES-AI-02、DES-AI-01 の改訂）

### 10.1 今の思考と、候補の比べ方

方式の選び方:

- `ai = "charge"`（突っ込む）/ `"hold"`（待つ）は、動き出す条件として残す
- それとは別に `approach = "direct"`（まっすぐ寄る。省略したときの値）/ `"group"`（一団でそろってから入る）を足す
- `group` の方式には、空でない `group`（一団の名前）が必要。同じ一団の方式はそろえる
- 章のデータで敵ごとに選び、すべての敵を一団の方式にはしない
- 今の `Charge`・`Hold` に新しい意味を兼ねさせず、`UnitSetup`・`Unit` に `Approach` と `Group` を持たせる

一団の方式の動き出し:

- `hold` で一団の方式の敵は、一団のだれかに攻撃の候補ができたとき、または `charge_group` で動き出したときから集まり始める。それまでは待つ
- 攻撃の候補ができても、一団の方式なら下の集まりの決まりを先にかけ、1 体だけで攻撃に向かわない
- `hold` でまっすぐ寄る方式の敵は、今どおり、攻撃できたら `Charge` になる

候補の比べ方:

- 候補は「着くマス・相手・使える攻撃の武器」の組
- 優先の順は次のとおり（1〜5 は今と同じ）
  1. 通常ダメージ × 攻撃の回数 ≧ 相手の HP（倒せる）
  2. ダメージ × 表示の命中率 × 攻撃の回数 が大きい
  3. 反撃の同じ積が小さい
  4. 自軍の添字が小さい
  5. 着くマスの Y・X が小さい
  6. 武器の列の添字が小さい
- 必殺・大盾の期待値と乱数は使わない
- 途中で打ち切らず、すべての候補を決まった順で比べる
- まっすぐ寄る方式は、攻撃の候補がなければ、今の「近さ」（DES-AI-01）を小さくする寄り方を保つ
- 集まっている間だけ、下の決まりで候補を絞る。弱い相手を狙う新しい優先は作らない

### 10.2 一団でそろってから入る決まり（Q-DES06-08。E-89 で決定）

割に合わない相手:

- 各敵から見て、次のどちらかに当てはまる自軍を「割に合わない相手」とする
  - 相手からその敵への予測の通常ダメージの合計が、敵の今の HP 以上
  - 両側とも「ダメージ × 命中率 × 攻撃の回数」で比べて、相手からその敵への値が、敵から相手への値以上
- 比べるときは、それぞれその位置で使える武器の最もよい候補を使う
- 大盾・必殺・将来の味方の攻撃は数えない
- この判定は、下がる相手を決めるのに使い、攻撃する相手を弱い順に選ぶのには使わない（Q-DES06-08）

危険な範囲:

- 割に合わない相手が到達できるマス（`Reachable`）と、すべての攻撃の武器の射程を合わせた範囲を、その敵にとっての危険な範囲とする
- 待つ敵かどうかにかかわらず、自軍の次の移動 ＋ 攻撃の範囲を使う
- 割に合うかの比べ方は、相手の到達できる位置ごとに、敵の今の位置へ正しく攻撃できる候補を並べて行う。その位置で敵が反撃できないときは、敵の側の合計を 0 とする
- 相手の候補が複数あれば、10.1 節の比べ方で最もよいものを選ぶ
- 到達できない・射程の外なら、危険な相手として数えない

集まる先:

- 集まる先は、危険な範囲のすぐ外の通れるマス（危険な範囲と上下左右で接する、安全なマス）のうち、同じ戦場の自軍への「近さ」が小さいもの
- 一団の誰にとっても危険な範囲がないあいだは、ふつうの敵（`Charge`）と同じ候補の比べ方で寄り、届けば攻撃する。ただし入った状態にはしない。危険な範囲ができたら集まり始める（開発者の決定 2026-11-01「寄るだけで入らない」「危険がなければ普通に攻撃」、REV-074 の R-01・T-02）
- 集まり始めた一団で、自分にとって危険な範囲がない一員は、ほかの一員の集まる先に上下左右で隣り合う通れるマスのうち、自軍から遠い（後ろ側の）マスへ割り当てる。すでにそのようなマスにいれば動かない（開発者の決定 2026-11-01「仲間の後ろ側の隣」、REV-074 の R-02・T-01）
- 安全な集まる先は、生きている敵の添字の順に、距離の費用 → Y → X の順で、重ならないように割り当てる
- 境目の比べ方は、近さ → そこまでの地形の費用 → Y・X。後ろの列の候補も同じ順で比べる
- 移動には自軍に近づく今の経路を使う。別の経路を回って弱い敵を探す機能は足さない

一斉に入る判定:

- 集まる先の割り当てと一斉に入る判定は、敵軍の番の始め（増援・砦の回復のあと）に一度行い、その番の間は変えない
- 集まり始めた一団は、割り当てた集まる先を番をまたいで保ち、全員が着くまで入らない。危険な範囲が空になったこと（先頭が安全なマスに着いて、今の位置を攻撃できる自軍がいなくなったときなど）だけでは入らない（開発者の決定 2026-11-01、REV-074）
- 番の途中で一団が動き出したら、次の敵軍の番から集まりに加わる。処理し終えた敵をやり直さない
- 加わる敵は、動き出していて、生きていて、出てきていて、同じ到達できる領域にいる、一団の一員
- 全員が割り当てられた集まる先に着いていたら、その番に全員で入る
- 先頭の敵がその番に着いただけでは、後ろの敵も含めて突然入ることはしない
- 入った状態は一団に持たせ、集まり直しを繰り返さない
- 戦死した敵と、まだ出ていない増援は待たない

集まれないとき:

- 集まっている間に、安全な集まる先へその番で届かない敵は、安全な範囲のうち、割り当てた先までの移動の費用が最も小さいマスへ寄る
- すでに危険な範囲の中にいる敵は、すぐ逃げられるなら集まる先へ下がる。逃げ場がなければ、ふつうの候補の比べ方で攻撃する
- 安全な集まる先を人数分取れない狭い道では、取れた最も前の列に隣り合う安全な範囲に、後ろの敵を割り当てる
- 安全な範囲そのものが足りなければ、今の位置で待つ
- 離れた、到達できない領域にいる一員は、別に集まりを判定する。まだ出ていない仲間を理由に止まらない
- 狭い道で集まれずに止まり続ける配置は、制作の不備として試遊で直す
- 時間切れで無条件に突っ込む決まりは足さない

### 10.3 敵の騎兵が下がる先

行動のあとの盤面で、残りの移動力で行けるマスを並べ、次の順で選ぶ。

1. 自軍の次の移動 ＋ すべての攻撃の武器の攻撃範囲に入る人数が少ない
2. 最も近い生きている自軍からのマンハッタン距離（縦と横の差の和）が大きい
3. 今の位置からの費用が少ない
4. Y・X が小さい

- 今の位置も候補に入れ、動かないほうがよければ動かない
- 反撃を受けて倒れた敵は再移動しない
- 集まっている間に例外として攻撃したときも、同じ下がり方を使う
- 下がったあとに、一団の集まり直しはしない

### 10.4 思考の時間（NFR-02）

- 32×32・一度に 46 体（自軍 7・敵 39。TBD-11 の改訂、E-91）、手持ちは最大 5 なので、候補はおおむね「敵の数 × 着くマス × 自軍の数 × 武器の数」
- すべての行動の先の組み合わせを探すことはしない
- 到達できる範囲・自軍の危険な範囲・近さは、同じ盤面の間は使い回す。移動・戦死・出現・装備の変更のあとは捨てる
- 一団の入る判定を、敵 1 体ごとにやり直さない
- 調べる順と同点の決まりを固定し、使い回しの有無で結果を変えない
- 「1 秒以内」の要求は保つが、今回の設計を作ったことで達成したとはしない
- E-72 に従い、待ちを感じたら、外側で敵軍の番の思考の時間（再生の時間を除く）を測り、盤面・体数・持っている武器・環境・時間を記録する。core に時計は入れない
- 遅いときは局所的な計算し直しを見直し、思考や再移動を黙って範囲から外さない

## 12. 画面と入力

### 12.1 武器の選択（DES-UI-26）

攻撃:

- ふつうの流れは、移動先 → 攻撃 → 武器 → 相手 → 予測 → 決定
- 攻撃の武器を 1 本だけ持つときは、武器の一覧を省いて相手の選択へ進む。取り消しは 予測 → 相手 → 行動の一覧 の順になる（開発者の承認（2026-10-31、REV-072））
- 武器の一覧は最大 5 行。名前・物理／魔法・威力・命中・必殺・重さ・射程・特効の対象を詳しい欄に出す
- 相手に届く武器がなければ、理由を表示する
- 決定するまで、core の装備は変えない
- 右クリック・Esc は、予測 → 相手 → 武器 → 行動の一覧 → 移動先の選択 の順に戻る。決めていない移動と武器を取り消せる

回復:

- 行動の一覧 → 杖の選択 → 相手 → 回復の予測
- 杖を 1 本だけ持つときは、杖の一覧を省く。取り消しは 予測 → 相手 → 行動の一覧 の順になる（開発者の承認（2026-10-31、REV-072））
- 錬金術師には、攻撃と回復の両方を出す

準備:

- 道具と武器を同じ 5 枠として「3/5」のように表示し、武器の列の先頭に「初めの装備」と付ける
- 在庫と名簿はスクロールし、9 人目・5 枠目でも案内やボタンと重ならない
- 装備できない武器は、選べない理由を出す

### 12.2 予測と情報

予測:

- 「通常ダメージ × 攻撃の回数」「命中率」「必殺率」「攻撃の速さ」を両側に出す
- 特効は文字で強調し、効く威力を詳しい欄に出す
- 大盾 30%・怒り ＋50 の条件・狙撃・鼓舞の説明は残す。「必殺」と確定で出す今の表示はやめる
- 武器の重さで速さがいくつ落ちたかと、反撃できないことも分かるようにする

情報欄:

- 足した 3 つの能力と敵のレベル、装備と持っている武器すべて、キャラと兵種の両方のスキルを出す
- 「能力」「装備・スキル」の 2 ページに分け、クリックと Tab で切り替える。ページの切り替えは表示だけ
- 予測を開いている間は、予測の表示を優先する
- 長い名前を省いて表示しても、選んだ行の詳しい欄では全文を読める

### 12.3 再移動

- 行動の再生のあとに `PendingCanto`（待っている再移動）があれば、再移動の状態に入る
- 残りの移動力と、行けるマスを表示する。マスをクリックすると `CantoMove`、今の位置のクリック・「終える」・Esc で `CantoEnd`
- まだほかのユニットを操作できないことを案内する
- 攻撃を決める前の取り消しと、結果が出たあとの再移動の終わりを分ける
- 巻き戻しは、ふつうと同じ入口から移動の前へ戻す
- 敵の再移動はふつうの移動として再生し、攻撃の前後の移動が履歴の同じ 1 行に入る

### 12.4 操作 4 点（DES-UI-27）

1. 配置の画面では、`DeploymentView`（配置の盤面）の初めの敵にカーソルを当てると能力を表示する。敵をクリックしても、味方の配置を入れ替えない。まだ出ていない増援は見せない
2. 情報欄に出すものの優先の順は「予測などの専用の表示 → カーソルの下の生きているユニット → 選んでいるユニット → 地形」。カーソルが盤の外や空いたマスに出たら、選んでいるユニットに戻る。表示の切り替えは、選択と配置を変えない
3. 敵の範囲は、出している敵の添字の集まりで持つ
   - ふつうに敵をクリックすると足し、同じ敵をもう一度クリックすると消す
   - 自軍を選んだりスクロールしたりしても保つ。位置・装備・生死が変わったら計算し直す
   - 戦死した敵は除く。別の `Battle` では空にする
   - 巻き戻しに成功したときも、同じ添字の集まりを戻った盤面に照らし、生きている敵だけを表示する
   - Q キーで出す全部の敵の範囲とは別の設定で、重なったマスは合わせた範囲にする
4. 自軍の移動先を選んでいる状態で敵をクリックしたら、範囲を出すより、敵をクリックして攻撃する操作を優先する
   - 移動できる攻撃の位置と手持ちの武器を並べ、まず武器の選択へ進む
   - その武器で「今の位置から攻撃できれば今の位置、そうでなければ移動の費用が最も小さいマス、同じなら Y・X の小さいマス」を仮の移動先に選ぶ
   - 予測の上で移動先を示し、ふつうの確認で決める
   - 候補がなければ理由を出し、移動先の選択の状態を保つ
   - この操作でも、すぐに乱数を引かない

### 12.5 ミニマップ（DES-UI-28）

配置:

- 窓は 832×576。盤面は今の左 512×512（16×16 マス）を保ち、**情報欄を狭くする**
- 右の情報欄は x = 512〜831、y = 0〜359 の 320×360。右下の x = 512〜831、y = 360〜511 の 320×152 をミニマップだけに使う
- 下の案内欄 y = 512〜575 は今のまま
- 地図の本体は x = 608〜735、y = 376〜503 の 128×128 の中に、縦横の比を保って縮める
  - 横は欄の中央に置く（左右の余白 96 px ずつ）
  - 縦は、上に見出しの 16 px を取り、下の余白を 8 px にする
  - 余白に枠と凡例を置く
- 32×32 なら 1 マス 4 px、16×16 なら 8 px。長方形のマップは中央に寄せて余白を付ける

描くもの:

- 地形の色、自軍は青・敵は赤、今の表示範囲の白い枠、分かっている予兆だけ
- 全滅した敵、まだ出ていない増援の位置は表示しない
- ふつうの戦闘・配置・巻き戻しの下見では、それぞれが参照している `BoardView`（盤面の見え方）で常に出す
- メニューや予測を地図の上に重ねない
- 情報欄のページ送りでミニマップは動かない

入力:

- 地図をクリックすると、カメラの中心をその位置へ移し、`Camera` の今の上限で止める（Q-DES06-10。E-89 で決定）
- ドラッグは足さない。余白のクリックは無視する
- 移動・攻撃の操作としては扱わず、乱数の状態・履歴・敵の範囲の設定を変えない
- 再生中の自動の追いかけ（Playing）の間はクリックでの移動を無効にし、再生のあとはふつうの入力に戻す
- 下の行の地図でも敵の選択と取り違えないよう、入力の判定はミニマップ → 情報 → 盤面の順（Q-DES06-10）
