ゲームには音が一切なかった。新作に、(1) 効果音と BGM を再生する仕組み、(2) 開発者があとで本物の音に差し替えられる形の**仮の音**、(3) 画面の操作・戦闘の出来事への結び付けを足す。

範囲外（作らない）: 本物の曲・効果音の制作、音量の保存、設定画面、既存の作品への音の追加、core の変更。

**この音は本物ではない。** `tools/synth` が、決まった乱数の種から毎回同じ WAV を合成した「仮の音」である。曲の旋律もその場で作った断片で、既存の作品や有名な曲の旋律は使っていない。

## 3. 再生の仕組み（DES-NG-09）

### 3.1 音の名前

型 `audio.SE`・`audio.BGM`（文字列）。ファイルは `audio/se/<名前>.wav`・`audio/bgm/<名前>.wav`。定数のすべてに WAV があることをテストで確かめる。

- 効果音: `select`・`confirm`・`cancel`・`hit`・`miss`・`critical`・`heal`・`blast`・`levelup`・`win`・`lose`・`step`
- BGM: `title`・`story`・`prepare`・`battle`。`BGMNone`（空）は「止める」

指示の例にあった `victory`・`defeat` の BGM は作らない。BGM の長さを 20〜40 秒にすると、6 曲では合計が 5 MB を超えるため。勝敗は効果音のジングル（`win`・`lose`）で表し、結果・ゲームオーバーの場面は BGM を止める。

### 3.2 `Backend`（再生の口）と `Sound`（管理）

`Backend` は interface。実装は `OpenOto`（oto）と、テスト用の偽物。PCM は 22050 Hz・16 bit・ステレオ（読み込み時にモノから直す）。

`Sound` の規則:

- `media` が nil なら、デバイスを開かず全体を無音にする。stderr にも出さない（既存の作品）。nil の `*Sound` も何もしない
- ファイルがない音は飛ばす（誤りにしない）。WAV が壊れている（読めない・データがない）音は、stderr に 1 回だけ出して飛ばす
- WAV は初めて鳴らすときに読み、結果（読めなかったことも）を覚える
- デバイスを開けない・初期化に失敗した（panic を含む）ときは、stderr に 1 回だけ出して無音で続ける。鳴らしている最中にデバイスが使えなくなったとき（`Backend.Err`）も、1 回だけ出して無音にする
- BGM はループ。`PlayBGM` は今と同じ曲なら何もしない（途切れさせない）。別の曲なら切り替える。ファイルがない曲は今の曲を止める。`BGMNone` は止める
- 効果音は重ねて鳴らせる（同時に鳴らす数の上限は 3.4 節）
- 音量: 効果音 0.7（`SEVolume`）、BGM 0.3（`BGMVolume`。小さめ）。別々の定数
- **ミュート**: キーで切り替える。ミュート中は効果音を鳴らさず、BGM は音量 0 で鳴らし続ける（解除すると続きから聞こえる）

### 3.3 oto を直接使う理由と、デバイスなしの扱い

Ebitengine の `audio.Context` は、デバイスの初期化の失敗を `RunGame` の誤りにして、ゲームを止める（フレームごとの hook が誤りを返す）。「デバイスがなければ無音で続ける」を守れないので、`audio.Context` は使わず、その下の oto（`github.com/ebitengine/oto/v3`）を直接使う。WAV の読み込み（リサンプリング）だけ `ebiten/v2/audio/wav` を使う。

この環境（音のデバイスなし）で `OpenOto` を呼ぶと、`NewContext` は成功し、最初のフレームの `Err()` が `snd_pcm_open` の誤りを返す。`Sound.Tick` がそれを 1 回だけ stderr に出して無音にする。
ALSA ライブラリ自身も、デバイスがないと `ALSA lib ...` の行を stderr に出す（こちらでは止められない）。

### 3.4 鳴らす数の上限（うるさくならないように）

- 1 フレームに鳴らす効果音は 3 つまで（`MaxSEPerFrame`）
- 同じ効果音は 6 フレーム（0.1 秒）あけるまで鳴らさない（`MinSEInterval`）。早送り（1 出来事 4 フレーム）では、続く同じ音の 2 つ目が飛ぶ
- 同時に鳴っている効果音は 8 つまで（`MaxVoices`。`Backend` が守る）
- 爆発が多数に当たる `EventBlastHit` は音を付けない。爆発の音（`blast`）が 1 回鳴るだけ

飛ばした音は、あとから鳴らさない（遅れて鳴ると、画面とずれるため）。

## 4. 結び付け（DES-NG-09）

### 4.1 `Game` への足し方

`Game.Update` を、「`update`（これまでの `Update` の中身。名前を変えただけ）を呼び、そのあとに `syncSound` を 1 回呼ぶ」に包む。`g.sound.sound` が nil（media なし）なら何もしない。既存の入力・描画・状態は変えない。
`syncSound` は、1 フレームの終わりに次を順に行う。

1. `Tick`（数の上限の数え直し・デバイスの異常の確認）
2. ミュートのキー（**N**）で切り替え
3. 操作の効果音（4.4 節）
4. 場面が変わっていたら BGM を切り替え（4.3 節）
5. 戦闘の出来事の再生が次の出来事へ進んでいたら、その出来事の音（4.2 節）

### 4.2 出来事 → 効果音

出来事の再生（`Controller.Event`）が新しい出来事を表示したフレームに、1 回だけ鳴らす。

| 出来事 | 条件 | 効果音 |
|---|---|---|
| `EventStrike` | `Hit` でない | `miss` |
| `EventStrike` | `Hit` かつ `Crit` | `critical` |
| `EventStrike` | `Hit`（それ以外。大盾で防いだ命中を含む） | `hit` |
| `EventHeal` | | `heal` |
| `EventBlast` | | `blast` |
| `EventBlastHit` | | なし（爆発の音で足りる。多数に当たっても 1 回） |
| `EventLevelUp` | | `levelup` |
| `EventWon` | | `win`。BGM を止める（ジングルを聞かせる） |
| `EventLost` | | `lose`。BGM を止める |
| `EventMove` | | `step`（小さな足音。同じ音は 0.1 秒あけるので、連続移動でもうるさくならない） |
| そのほか（`EventFall`・`EventExp`・`EventWait`・`EventPhaseStart` など） | | なし |

### 4.3 場面 → BGM

| 場面 | BGM |
|---|---|
| `Title`・`RuleSelect` | `title` |
| `Story`・`Joined`・`Clear` | `story` |
| `Prepare`・`Deploy` | `prepare` |
| `Battle` | `battle`（`EventWon`・`EventLost` で止まる） |
| `Result`・`GameOver` | なし |

同じ BGM の場面どうしの移動（`Title` → `RuleSelect`、`Prepare` → `Deploy`）では途切れない。場面が変わったときだけ切り替えるので、戦闘中に勝敗で止めた BGM が、同じ場面のうちに勝手に戻ることはない。

### 4.4 操作 → 効果音

| 入力 | 効果音 |
|---|---|
| 右クリック・Esc（取消し） | `cancel` |
| 左クリック、物語の送り（Enter・Space。`Story` のときだけ） | `confirm` |
| Tab・I・Q（情報欄・詳細・危険範囲の切り替え） | `select` |

同じフレームに複数あれば、取消し → 決定 → 選択の順で 1 つだけ鳴らす。操作が実際に受け付けられたかは見ない（何もないところの左クリックでも `confirm` が鳴る）。仮の割り当てで、本物の音を入れるときに見直す。

### 4.5 ミュートのキー（設計への提案）

指示は M キーだったが、**M は全体図（DES-UI-30、承認済み）が使っている**。M を取ると既存の動作が変わるので、ミュートは **N** にした（`ui.MuteKey`）。M にしたいときは、全体図のキーも含めて人が決める。

## 5. 仮の音の合成（`tools/synth`）

- 標準の Go だけで、16 bit・モノ・22050 Hz・44 バイトヘッダの WAV を書く。出力先は `data/alchemy/media/audio/se/`・`bgm/`（`-out` で変えられる）
- 乱数は自前の xorshift64*（Go の版が変わっても列が変わらない）。音ごとの種を固定する（効果音 1101〜1112、BGM 2101〜2104）。**毎回同じバイト列**になる（TC-DES-NG-09-01）
- 部品: 発振器（正弦・三角・矩形・パルス 25%・のこぎり・鐘）、指数で減る包絡（立ち上がり・余韻は最小でも数 ms 取り、プチ音を出さない）、周波数が動く音、ローパスをかけたノイズ、こだま（帰還のある遅れ）、最大振幅の正規化
- 効果音の最大振幅は 0.4〜0.95、BGM は 0.7。クリップしない（97% 以下をテストで確かめる）

### 5.1 効果音

| 音 | 作り方（約何秒） |
|---|---|
| `select` | 正弦波 1320 Hz と倍音の短い電子音（0.12） |
| `confirm` | 三角波の上がる 2 音 880 → 1320 Hz（0.3） |
| `cancel` | 三角波の下がる 2 音 660 → 440 Hz（0.3） |
| `hit` | ノイズの破裂（カットオフ 4000 → 600 Hz）と、200 → 60 Hz に落ちる正弦波（0.3） |
| `miss` | 山形の包絡のノイズ（カットオフ 800 → 3500 Hz）。空を切る音（0.3） |
| `critical` | 命中の音に、300 → 50 Hz の低音と、鐘 1568 Hz・2093 Hz の余韻（0.7） |
| `heal` | 鐘の上がる 4 音（C5・E5・G5・C6）と高い音のきらめき、こだま（0.9） |
| `blast` | 破裂のノイズ、140 → 30 Hz と 90 → 28 Hz の落ちる低音、600 → 80 Hz のこもった轟き（約 1.8 秒）、乱数で散らした 14 個の破片の音。爆弾の迫力のため、ほかより長く大きい（2.0） |
| `levelup` | 矩形波と三角波の上がる 5 音（C5・E5・G5・C6・E6）の短いファンファーレ（1.4） |
| `win` | 上がる分散和音 G4・C5・E5・G5 のあと、C メジャーの和音を伸ばす（2.4） |
| `lose` | 下がる 4 音 E4・D4・C4・A3 のあと、A マイナーの低い和音を伸ばす（2.8） |
| `step` | ノイズの小さな足音と短い低音（0.1） |

### 5.2 BGM（どれも 20 秒、ループ）

どの曲も、小節数 × 4 拍の長さがちょうど 20 秒になるように、テンポと小節数を決めた。端をはみ出す音とこだまは反対の端へ回り込ませる（`track.loop`）ので、末尾から先頭へ継ぎ目なくつながる。テストで、末尾の標本と先頭の標本の差が、曲の中の隣り合う標本の差の最大を超えないこと、満点の 3% 未満であることを確かめる（TC-DES-NG-09-04）。

| 曲 | テンポ・小節 | 音階・コード進行 | 楽器の波形と音使い |
|---|---|---|---|
| `title` | 72 BPM・6 小節 | D ドリアン。Dm・B♭・Gm・Dm・B♭・A | 三角波のパッド（わずかにずらした 2 つの発振器、立ち上がり 0.6 秒）、正弦波の低音（D2 など）、三角波の 8 分音符のアルペジオ、鐘の旋律（D5・C5・A4 ... の下降を中心に、最後は E5・C♯5）、付点 8 分のこだま |
| `story` | 60 BPM・5 小節 | E フリジアン。Em・F・Em・Dm・C | E1 の正弦波の持続低音（5 秒ごとに立ち上げて重ねる）、正弦波と三角波の静かなパッド（立ち上がり 1.2 秒）、E フリジアンの音（E5・G5・B5・A5・F5 など）のまばらな竪琴風の音、20 秒に 2 周期でゆっくり揺れる低いノイズ（風）、長いこだま（0.9 秒）。古代都市の静けさ |
| `prepare` | 96 BPM・8 小節 | A マイナーから C メジャー。Am・F・C・G・Am・F・G・Em | 三角波の低音（根音と 5 度を 8 分で行き来する）、パルス波のアルペジオ、はじく三角波の旋律、8 分の裏拍の軽いハイハット |
| `battle` | 120 BPM・10 小節 | D ハーモニックマイナー。Dm・Dm・B♭・A・Dm・Dm・Gm・A・B♭・A | D1 の長い低音、のこぎり波と正弦波の 8 分音符の低音（4・8 拍目で 1 オクターブ上）、パルス波の 16 分音符のアルペジオ、拍 1・3 の控えめなキック、拍 2・4 のノイズのスネア、3・7・10 小節目の短い旋律の断片（D・C♯・A など。矩形波のずれた 2 重） |

コード進行は一般的な組み合わせで、旋律は、このためにその場で作った短い音の並びである（既存の曲を参考にしていない）。

## 6. 台帳と検査

`data/alchemy/media/ASSETS.md` に、音ごとに 1 行を書く。列は画像の台帳 `ASSETS.md` と同じ 7 列（ファイル・作り方・使ったツールと版・生成した日・指示または出典・利用条件・確かめた日・確かめた人）。作り方は「自作（合成。tools/synth、乱数の種 N）」、利用条件は「自作。CC0 1.0 として扱う（既存の自作の画像と同じ条件。ライセンスの原本はない）」。行は `go run ./tools/synth -ledger` でも出せる。
画像の台帳の検査（`data.CheckMediaLedger`）は、作り方が「自作」で始まることを求める。そのため「合成」で始めず、「自作（合成。…）」にした。

台帳は、画像と同じ `ASSETS.md` の 1 つにまとめた（統合は親エージェントが行った）。音だけを突き合わせる `internal/ui/audio/ledger_ng03_test.go` は、`ASSETS.md` を読む形に直して残している。

audio の下のすべての WAV が行を持つこと、行のファイルが実在すること、7 列が埋まっていること、WAV の合計が 5 MB 以下であることを、`audio` のテストで確かめる（TC-DES-NG-09-17・18）。

## 7. 差し替えの手順（本物の音を入れる）

1. 本物の WAV を、**同じ名前**で `data/alchemy/media/audio/se/<名前>.wav`・`bgm/<名前>.wav` に置く（上書きする）。形式は、16 bit PCM の WAV なら、モノでもステレオでも標本化周波数が違っても読める（読み込み時に 22050 Hz のステレオへ直す）。BGM は、ループ点を整えた長さで作る
2. `ASSETS.md` の、その行を書き直す。作り方・使ったツールと版・指示または出典・利用条件・確かめた日・確かめた人を、実際のものにする
3. `tools/synth` を実行すると、仮の音で上書きされてしまう。差し替えた音は、`tools/synth` の `seAssets`・`bgmAssets` から外す
4. 音を足すとき（新しい名前）は、`internal/ui/audio/names.go` の定数と `AllSE`・`AllBGM`、`internal/ui/sound_ng03.go` の対応表、この文書の表、台帳を足す

BGM の長さの検査（20〜40 秒）は、`internal/ui/audio` のテストが読み込んだ WAV で確かめる。本物の曲がこの範囲に収まらないときは、テストの範囲を直す。

## 8. ビルドの依存

- `go.mod` に `github.com/ebitengine/oto/v3`（Ebitengine の audio が使う音の出力）を足した。Linux では cgo で ALSA を使うため、**手元でビルドするときは `libasound2-dev` が要る**（Debian・Ubuntu の場合）。CI の apt-get にも足した。実行時に ALSA のデバイスがなければ、無音で続ける（3.3 節）。実行ファイルは `libasound.so` を読み込むので、実行する環境にも ALSA のライブラリ（`libasound2`）は要る
- Windows 向けのビルドは cgo を使わず、影響はない
- `go.mod` の oto は `// indirect` のまま、`internal/ui/audio` が直接 import している。ビルドと検査には影響しない。`go mod tidy` を実行すると、`// indirect` が外れる

## 9. 未確認・持ち越し

- 実際のデバイスでの再生（ミュート・BGM の切り替え・効果音の重なり）は、この環境ではデバイスがなく、確かめていない
- 操作の効果音の割り当て（4.4 節）は仮
- 音量の保存・設定画面は範囲外
