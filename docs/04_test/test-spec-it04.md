## 1. 方針

| 項目 | 内容 |
|---|---|
| テストケース ID | `TC-<要求ID>-<連番2桁>`。反復 1〜3 の最後の番号の次から振る |
| コードとの対応 | 表駆動テストを基本とし、サブテスト名に ID を入れる。正常・境界・異常を確かめる |
| 未実装の扱い | 種別に「自動・未実装」を明記する。tccheck は仕様書とトレーサビリティにありコードにない ID を警告とする。警告を手動確認済み・実装済みの根拠にしない。ダミーのテストや ID だけのコードは追加しない |
| 書き足し方 | 各担当が自分のケースだけを具体化・実装し、種別の「未実装」を外してトレーサビリティの担当範囲も更新する |
| 期待値 | 実装の出力を写さず、要求と設計から導く。既知の期待マスと閲覧を挟まない対照戦闘を使い、同じ実装同士の比較だけで済ませない |
| 乱数と状態不変 | 実 PCG・履歴・出来事境界・進行位置・回数・Campaign・次の seed を含めて確認する。返り値の深い写しと元状態を検証する |
| 既存ケースの改訂 | DES-IT04 8.3 節の各実装 Issue が、ID と変更対象外の規則を保ち、元の仕様書・コード・トレーサビリティの担当行を同時に直す。Issue A に該当する既存ケースはない |
| 表の取り込み | 列数・行末の区切り・表内の空行と、双方の変更した要求・ケースの行を照合する（REV-031、REV-033、REV-042） |
