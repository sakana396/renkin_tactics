### 2.2 Q（全敵の危険範囲）の計算を覚える（#227）

試遊で「Q で危険範囲を出すと、味方をすぐ動かしにくい（反応が遅い）」との指摘があった（新作・1 マス 48 px・敵が多い）。`Controller.Danger` が呼ばれるたびに全敵の移動範囲と攻撃範囲（ZOC 込み）を計算し直していたので、盤面の状態（位置・生死・陣営・移動力・粘着・武器の射程）が前と同じなら前の結果を返すようにした。設計の中身（危険範囲の求め方・表示）は変えない。

| ID | 対象（要求・根拠） | 前提 | 入力・操作 | 期待結果 | 種別 |
|---|---|---|---|---|---|
| TC-NFR-01-05 | NFR-01 / DES-UI-08・29、#227 | 自軍 2・敵 2（うち動く敵 1）・2 ターン目の増援 1 の盤面。Q を出す | 変化がないまま Danger を 2 回呼ぶ。粘着瓶、番の切り替え（粘着の期限切れ）、増援の出現、自軍の移動、巻き戻し、Q の切り替えのたびに Danger を呼ぶ | 変化がなければ同じ地図を返す（計算し直さない）。変化のたびに、覚えた結果が計算し直した結果と一致する。粘着・増援・巻き戻しでは前の結果と変わる。Q を切ると nil、出し直すと正しい結果 | 自動・正常・境界（#227。覚えた結果の更新を 3 か所壊して落ちることを確認） |

#### 手動の測定（Update と Draw）

Windows 向けの試験の実行ファイルを `GOOS=windows go test -c -o ui.exe ./internal/ui` で作り、`internal/ui` で `RENKIN_227_DRAW=ch01`（または `ch03`）を付けて `ui.exe -test.run NONE` を動かす（WSL からは `WSLENV=RENKIN_227_DRAW` も付ける）。新作・48 px の戦闘で、場面ごとに 300 フレームの Draw（描画完了まで）と Update の時間を標準出力に出す（`danger_draw_227_test.go`）。基準の Windows PC（i5-10400F）での Draw の中央値は、1 章の Q ありで 4.00 ms から 3.51 ms、味方を選んだとき 4.17 ms から 3.86 ms、敵にカーソルを当てたとき 5.32 ms から 4.62 ms、3 章の Q ありで 3.50 ms から 3.00 ms、敵にカーソルで 5.25 ms から 4.54 ms。Update は計測の刻み（約 1 ms）より短かった。Q なしは 1 章 3.00 ms、3 章 2.01 ms。この環境では、Q ありの 1 フレームは 60 fps の枠（16.7 ms）に十分収まる。
