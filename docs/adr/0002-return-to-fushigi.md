# ADR-0002: 戦闘をふしぎ錬金に戻す形（独立したパッケージを写す）

- 状態: 案
- 日付: 2026-10-20
- 関連: TBD-03、CST-04、Q-06、E-02、E-11、E-17、IT01-PLAN H-04

## 背景

作り込んだ戦闘を、あとでふしぎ錬金に戻す（E-02、CST-04）。ふしぎ錬金の戦闘のコード（`internal/core/battle*.go`）は、World のフィールドと関数（`w.Battle`、`w.catalog`、`w.Inventory`、報酬の抽選、負傷の時刻）と結び付いていて、そのままでは持ち出せない。戻す形は反復 1 で決める（E-11）。

## 決定

- 戦闘の規則を、**ゲームの状態（World など）と定義データの型（`defs`）を知らない、独立したパッケージ** `internal/core/tactics` に作る（E-17）
- `tactics` は Go の標準ライブラリだけに依存する。入力（マップ、ユニット、クラス、武器、アイテム、地形）は `tactics` が持つ型（`tactics.Setup`）で受け取る
- 定義データから `tactics.Setup` を組み立てる口は、`tactics` の外（このリポジトリでは `internal/core`）に置く
- ふしぎ錬金に戻すときは、`internal/core/tactics` をふしぎ錬金の同じ場所に写し、ふしぎ錬金の `core` に「World と定義データから `tactics.Setup` を作る口」と「結果（勝敗、倒れたユニット、使ったアイテム）を World に返す口」を書く
- 写すときは、写した元のコミットをふしぎ錬金のコミットメッセージに書く（AGENTS.md）

## 理由

- 戦闘が World を知らなければ、ふしぎ錬金の側で直す箇所を「結ぶ口」に寄せられる見込みがある。本当にそうなるかは仮説で、H-04 で数えて確かめる
- ふしぎ錬金も `internal/core` の下に置けるので、AGENTS.md のパッケージ構成（`core` は `defs` のみに依存）を崩さない
- 写す形なら、2 つのリポジトリの版を合わせる手間がない。ふしぎ錬金は反復 6 で中断しているので、戻すのは先になる

## 検討した選択肢

| 選択肢 | 判断 |
|---|---|
| 独立したパッケージを写す | **採用**（E-17） |
| Go のモジュールとして共有し、ふしぎ錬金が import する | 選ばなかった（E-17）。写さずに済むが、両方の版を合わせる手間がかかる。戦闘の形が固まったら、あらためて検討できる |
| 今は決めない | 選ばなかった（E-17）。World から切り離す形が決まらないと、反復 1 の設計が決まらない |

## 影響

- `tactics` の型と、`defs` の型が一部重なる（例: クラスの能力）。重なりは `internal/core` の変換で吸収する
- ふしぎ錬金の品質つきのアイテムの使用（ふしぎ錬金 DES-QLT-05）は `tactics` に入れない（E-07）。戻すときに必要なら、ふしぎ錬金の側で「品質から回復量を決めて `tactics` のアイテムに渡す」形にする
- 戻すと、ふしぎ錬金の戦闘の規則（素早さ順 → 自軍と敵軍の交互、前衛・後衛 → クラス）と、戦闘の画面も変わる
- アイテムの持ち方が違う。ふしぎ錬金は共有の在庫（`w.Inventory`）から使い、`tactics` はユニットごとの手持ちを持つ。戻すときは、戦闘の前に在庫から手持ちに渡し、戦闘のあとに使った分を在庫から減らす
- 反復 1 の振り返りで、H-04（結ぶのに要る型・関数の数と、ふしぎ錬金の側で直す箇所）を記録し、この ADR を見直す
