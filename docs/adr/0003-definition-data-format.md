# ADR-0003: 定義データの形式（TOML）

- 状態: 承認（E-19）
- 日付: 2026-10-20
- 関連: FR-SYS-03、FR-SYS-04、IF-03、E-17

## 背景

ユニット・クラス・武器・スキル・マップを定義データから読む（FR-SYS-03）。定義データは、人がテキストエディタで読み書きできる形式にする（IF-03）。

## 決定

- 定義データは TOML で書き、`github.com/BurntSushi/toml` で読む（E-17）。ふしぎ錬金の ADR-0002（定義データの形式）と同じ
- 本体の定義データは `data/base/` に置き、`go:embed` で埋め込む（AGENTS.md）
- マップの地形は、1 行を 1 つの文字列で書き、1 文字を 1 マスとする（例: `"..FF^^.."`）。文字と地形の対応は地形の定義に書く

## 理由

- ふしぎ錬金と同じ形式なら、戦闘を戻すときに定義データの書き方もそろう
- TOML はコメントが書け、人が読み書きしやすい。マップを文字の行で書けば、テキストエディタでも形が見える

## 検討した選択肢

| 選択肢 | 判断 |
|---|---|
| TOML | **採用**（E-17） |
| JSON | 選ばなかった（E-17）。標準ライブラリだけで読めるが、コメントが書けず、人が書くには読みにくい |

## 影響

- 外部のライブラリ `github.com/BurntSushi/toml` に依存する（`defload` だけが使う）
- 誤りの「位置」は、TOML の文法の誤りは行番号、意味の誤りはキーの道筋（例: `characters[2].class`）で示す（DES-DAT-03）
